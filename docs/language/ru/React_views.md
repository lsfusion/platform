*Представление React* — часть [интерактивного представления](../paradigm/Interactive_view.md) формы или [дизайна навигатора](../paradigm/Navigator_design.md), которую в веб-клиенте вместо платформы рисует компонент React. Статьи этого раздела описывают, что такой компонент получает и что вызывает.

Контейнер [`DESIGN`](DESIGN_statement.md) может отрисовываться компонентом React вместо стандартной раскладки. Компонент получает проекцию состояния формы и сам рисует всё поддерево контейнера. Таблицу, тулбар, управляющие элементы фильтров, группу фильтров и фильтр по свойству так же может рисовать собственный компонент React вместо их представления платформы ([Собственное представление компонента](React_component_views.md#component-views)). Вне формы компонент React может рисовать [окно навигатора](React_windows.md#navigator-window), [окно форм](React_windows.md#forms-window), [окно сообщений](React_windows.md#log-window) и [расположение окон](React_windows.md#window-layout).

Это возможность только веб-клиента. Десктоп-клиент десериализует контейнер и отрисовывает его обычное (не React) поддерево, а компонент с собственным компонентом React рисует представлением платформы, поэтому дизайн остаётся рабочим в обоих клиентах.

### Виды представлений React {#kinds}

Представления React бывают следующих видов:

- контейнер дизайна формы: имя компонента задаёт его `custom` в `DESIGN`, и компонент рисует всё поддерево контейнера ([Выбор компонента](#selecting-the-component));
- [собственное представление компонента](React_component_views.md#component-views): имя компонента задаёт `custom` таблицы дерева, тулбара, управляющих элементов фильтров, группы фильтров или фильтра по свойству, и компонент рисует на их месте то, что они показывают из своей группы объектов или дерева;
- [компонент React в `CUSTOM`](React_component_views.md#form-custom): имя компонента задаёт опция `CUSTOM` свойства или группы объектов, и компонент рисует одну ячейку свойства или строки группы;
- [окно или расположение окон](React_windows.md): имя компонента задаёт опция `CUSTOM` инструкции `WINDOW`, а для расположения — инструкции `NAVIGATOR`, и компонент рисует окно навигатора, окно форм или окно сообщений либо располагает окна.

Представление React на форме читает [проекцию формы](React_projection.md) и вызывает члены своего [контроллера](React_view_controller.md). Компоненты и хуки платформы для отрисовки строк, изображений и заголовков описаны в статье [Отрисовка в React](React_rendering.md); размещение того, что рисует платформа, — в статье [Компоненты, которые рисует платформа](React_platform_components.md); фокус, загрузка формы, клавиши и привязки мыши, живые данные и скрытое представление — в статье [Поведение формы в React](React_form_behavior.md); части группы объектов, которые рисует представление, — в статьях [Деревья, сортировки и выделение в React](React_trees_sortings_selection.md) и [Фильтры и тулбар в React](React_filters_and_toolbar.md). Контроллеры формы и навигатора, которые получает любое представление на JavaScript, описаны в статье [Контроллеры формы и навигатора](Form_and_navigator_controllers.md).

### Выбор компонента {#selecting-the-component}

В `DESIGN` атрибуту `custom` контейнера присваивается имя компонента строковым литералом, соответствующим `[A-Z][A-Za-z0-9_$]*` (простой идентификатор, начинающийся с заглавной буквы):

```lsf
FORM orders 'Orders'
    OBJECTS o = Order
    PROPERTIES(o) READONLY number, date, sum
;

DESIGN orders {
    BOX(o) {
        custom = 'OrderBoard';
    }
}
```

Форма значения выбирает отрисовщик: строковый литерал, соответствующий `[A-Z][A-Za-z0-9_$]*`, задаёт компонент React, а пустая строка `''`, строка с HTML-шаблоном или свойство дают [классический (не React) пользовательский контейнер](DESIGN_statement.md#containerprops). Здесь объект `o` отрисовывается компонентом React `OrderBoard` вместо стандартной таблицы. Компонент, не являющийся контейнером, принимает только имя компонента React — см. [Собственное представление компонента](React_component_views.md#component-views).

### Размер окна и базовый размер {#base-size}

Форме, открываемой окном (`SHOW ... FLOAT`; у `DIALOG` окно — расположение по умолчанию), размер вычисляется по содержимому в момент открытия и дальше не меняется: измеряется первая отрисовка компонента, по первым данным формы, а то, что он рисует позже, - новые строки, данные, пришедшие после открытия, - уже нет. Поэтому контейнеру, содержимое которого растёт после открытия, задают базовый размер: `size = (900, 600)` либо отдельные атрибуты `width` и `height`. Без него окно сохраняет размер первой отрисовки, а нарисованное позже содержимое вытесняет кнопки OK / Закрыть за край окна. Закладке (`WINDOW`) размер задаёт окно форм, поэтому там базовый размер не нужен.

Другой путь — не задавать базовый размер контейнеру React, а сделать динамическим само окно: в `DESIGN` самой формы задать её главному контейнеру `size = (-1, -1)` либо только `height = -1` — тогда ширина измеряется и фиксируется при открытии, а высота остаётся динамической. По каждому динамическому направлению окно следует за содержимым компонента, в том числе отрисованным позже. Это годится для формы, на которой нет таблиц (их высота перестаёт подстраиваться под строки), а высота содержимого умеренная: окно центрируется только при открытии, а его высота не ограничена экраном — окно выше экрана прокручивается целиком.

Базовый размер ограничивает и высоту самого контейнера, где бы форма ни открывалась. Без него высота контейнера — это высота того, что нарисовал компонент, и контейнеры над ним растут вместе с ним, поэтому компонент, нарисовавший больше, чем помещается на форме, растягивает всю форму, а прокручивается она целиком — в закладке её главный контейнер. Базовая высота (`height` либо `size`) отделяет размер контейнера от размера содержимого: контейнер получает её, по коэффициенту расширения (`fill`) расширяется из неё в свободное место формы, а не поместившееся содержимое прокручивается внутри него (`overflowVert` по умолчанию `auto`). Форму она растягивает, только когда сама в неё не помещается, — как базовый размер любого компонента.

### Компонент {#the-component}

`OrderBoard` — именованный экспорт из [модуля](Client_JavaScript_modules.md) `.jsx` в каталоге `src/main/web`. Примеры статей о React используют JSX. Для проекта [без сборки](Client_JavaScript_modules.md#without-the-build) поместите тот же компонент в файл `.jsx` — он преобразуется на сервере при отдаче. `import` и `export` там недоступны, поэтому ключевое слово `export` опускается, а компонент работает с предоставляемым платформой `window.React` — либо напишите его через `React.createElement` в обычном `.js`. Любой из этих файлов кладётся в `src/main/resources/web/init` (автозагрузка) или в `src/main/resources/web` с регистрацией через `onWebClientInit`.

Компонент — это обычная функция, получающая `props.data` и `props.controller`:

```jsx
export function OrderBoard(props) {
    const orders = props.data.o.list;
    return <div className="order-board">{orders.length} orders</div>;
}
```

Впервые компонент отрисовывается с первой проекцией своего контейнера, когда пришли первые данные формы, и никогда раньше: `props.data` имеет форму, описанную в статье [Проекция формы](React_projection.md), с самой первой отрисовки, поэтому ничего в нём не нужно проверять на ещё не пришедшую проекцию.

Компонент, который рисует одну строку, получает её как `props.row`, когда его отрисовывает [`List`](React_rendering.md#rendering-rows):

```jsx
function Row(props) {
    const r = props.row;
    return (
        <div className={r.current ? "order order-current" : "order"}>
            <span>{r.number.value}</span>
            <span>{r.sum.value}</span>
        </div>
    );
}
```

### Компонент React и HTML-шаблон {#choosing-between-a-react-component-and-an-html-template}

Компонент, который только размещает дочерние компоненты, которые рисует платформа, и ничего не читает из `props.data`, делает то же, что и классический пользовательский контейнер: HTML-шаблон располагает те же дочерние компоненты по своим местам `<Platform:name>`, без рантайма React и без узла-хоста на каждый из них. Если платформа рисует все дочерние компоненты контейнера, в `props.data` нет ни значений групп, ни значений свойств, поскольку такой компонент не проецируется, — только записи `{ caption, image, hidden }` дочерних компонентов в `props.data`.

Шаблону не даётся никаких данных. Он размещает то, что рисует платформа, по имени, а всё остальное в нём написано вручную: он не может прочитать ни заголовок потомка, ни его значок, ни заголовок самого контейнера. Заголовки, которые он показывает, рисует платформа: потомок-свойство рисуется по частям (если у него не задано `inline = FALSE`) — его заголовок и комментарий становятся отдельными местами, `<Platform:PROPERTY(qty).caption>` и `<Platform:PROPERTY(qty).comment>`, которые шаблон может поставить внутрь своей разметки, например в заголовок раздела, — любой другой потомок несёт свой заголовок внутри размещённого представления, а заголовок и значок самого контейнера платформа рисует рядом с контейнером, а не внутри шаблона.

И тот и другой называют свои дочерние компоненты, поэтому ни один из них не расширяется одним только `DESIGN`: чтобы добавить дочерний компонент, нужно изменить JSX или строку шаблона. Строка шаблона принадлежит объявившему её модулю и заменяется только целиком.
