*Функция отображения* — функция JavaScript, рисующая [пользовательское представление](../paradigm/Custom_views.md): вместо платформы она рисует строки группы объектов или значение свойства формы в [интерактивном представлении](../paradigm/Interactive_view.md). Её называет опция `CUSTOM` группы в блоке [`OBJECTS`](Object_blocks.md#objects) или свойства — в блоке [`PROPERTIES`](Properties_and_actions_block.md#options) либо среди [опций свойств](Property_options.md) в его объявлении. Называет её и атрибут `custom` таблицы группы `GRID(o)` или компонента свойства в [дизайне формы](../paradigm/Form_design.md) ([`DESIGN`](DESIGN_statement.md)). Функция возвращает объект из функций, которые вызывает платформа: `render`, `update` и необязательной `clear`. Вместо такой функции в тех же местах можно назвать компонент React ([Компонент React в `CUSTOM`](React_component_views.md#form-custom)). Функции отображения вызывает только веб-клиент.

### Функция отображения {#render-function}

Например, функция отображения группы объектов `itemCards` возвращает объект из двух функций, `render` и `update`:
```js
function itemCards() {
    return {
        render: (element, controller) => {
            ...
        },
        update: (element, controller, list) => {
            ...
        }
    }
}
```

Регистрируется именно функция: платформа сама вызывает _itemCards()_ и берет _render_ и _update_ из результата, поэтому нельзя регистрировать сам объект с этими функциями без обертки-функции. Её имя ищется сначала в реестре `window.lsfusion.custom`, где регистрируют свои экспорты загруженные [клиентские модули JavaScript](Client_JavaScript_modules.md#named-exports-and-auto-registration), затем среди имён глобального объекта `window`. Имя, зарегистрированное с видом `reactView`, — это компонент React.

Функция _render_ принимает на вход контроллер и элемент, внутри которого должны создаваться новые элементы, необходимые для отображения данных.

Для обновления отображаемых значений платформа будет каждый раз вызывать функцию _update_, в которую будет передан тот же _element_, что и в функции _render_, а также список значений _list_. Для свойства в `update` вместо списка передаётся его [значение](#property).

Объект может содержать и необязательную функцию `clear`, которую платформа вызывает при очистке представления [группы объектов](#diff) или ячейки [свойства](#property-controller).

### Строки группы объектов {#object-group}

В _list_ передается не весь набор объектов, а только считанная страница: для группы объектов с видом представления `CUSTOM` ее размер по умолчанию — 1000 объектов. Чтобы представление получало все объекты группы, задайте в блоке [`OBJECTS`](Object_blocks.md) опцию `PAGESIZE 0` (читать все объекты).

Названия полей объектов соответствуют названию свойств на форме. Значения свойств преобразуются в значения JS так же, как в строках [React-представления](React_projection.md#values): например, значения классов даты и времени передаются как `Date`, а `JSON` — как разобранный объект. Свойство, значением которого является объект, приходит числовым id этого объекта — тем же, которым объект передаётся в [запись FK и вызовы сервера](Form_and_navigator_controllers.md#value-formats). Каждый объект несёт также те же `key` и `objects`, что и строка представления React ([Идентификация строки](Form_and_navigator_controllers.md#row-identity-contract)).

Четвёртым аргументом, `options`, функция `update` получает значение опции [`OPTIONS`](Object_blocks.md#objects) группы (разобранный JSON).

### Контроллер группы объектов {#controller-methods}

Методы локального контроллера, передаваемого в _render_ и _update_, не считая служебных (необязательные аргументы — в скобках). Здесь `property` — интеграционное имя свойства, добавленного на форму в этой группе объектов, `object` — объект из списка _list_:

| метод | что делает |
| --- | --- |
| `isCurrent(object)` | является ли объект текущим в группе |
| `changeObject(object[, rendered[, element]])` | задает текущий объект группы (см. ниже); с `element` показывает рядом с ним [запись](../paradigm/Form_design.md#record) таблицы; `Promise` его запроса |
| `changeProperty(property[, object][, value])` | изменяет значение свойства или выполняет действие — на текущем объекте или на переданном (см. ниже); `Promise` его запроса |
| `batch(fn)` | выполнить `fn`; вызовы `changeProperty` и фильтров представления в ней уходят вместе, одним запросом; `Promise` этого запроса |
| `getValue(property, object)` | текущее значение свойства для объекта |
| `getCaption(property)` | заголовок свойства |
| `isPropertyReadOnly(property, object)` | доступность свойства для правки: `null` — редактируемое, `false` — только чтение |
| `getBackground(property, object)` / `getForeground(property, object)` | цвет фона / текста ячейки |
| `getFont(property, object)` | шрифт ячейки |
| `getPlaceholder(property, object)`, `getPattern(property, object)`, `getRegexp(property, object)`, `getRegexpMessage(property, object)`, `getTooltip(property, object)`, `getValueTooltip(property, object)` | значения одноименных атрибутов дизайна свойства |
| `getCaptionClass(property)`, `getGridClass(property, object)`, `getValueClass(property, object)` | CSS-классы, заданные одноименными атрибутами дизайна |
| `getChangeKey(property, object)` / `getChangeMouse(property, object)` | заданное на форме сочетание клавиш / событие мыши, изменяющее свойство |
| `getPropertyCustomOptions(property, object)` | значение опции `OPTIONS` свойства (разобранный JSON) |
| `getPropertyValues(property, value[, mode], ok[, fail][, count])` | список подсказок значений свойства с сервера |
| `diff(list, fnc[, noDiffObjects][, removeFirst])` / `clearDiff()` | вычисляет изменения списка (см. ниже) |
| `setBooleanViewFilter(property, pageSize)` | фильтрует представление условием «значение свойства истинно»; `Promise` его запроса |
| `setDateIntervalViewFilter(startProperty, endProperty, pageSize, start, end)` | фильтрует представление по интервалу дат; `Promise` его запроса |
| `getColorThemeName()` | имя текущей цветовой темы: `'LIGHT'` или `'DARK'` |
| `form` | [контроллер формы](Form_and_navigator_controllers.md) |

Если второй параметр `changeObject` (_rendered_) не указан, он считается равным _false_, что означает, что сервер должен в итоге вызвать функцию _update_ с новым списком объектов (возможно тем же).

`changeProperty` понимает свои аргументы по их количеству, а единственный аргумент — по нему самому: без аргументов он выполняет событие изменения свойства (для действия — само действие) на текущем объекте; с одним аргумент считается строкой, и событие изменения выполняется на ней, если это строка данных или дескриптор `objects` либо если свойство — действие, нарисованное в группе объектов; всё остальное — значение, которое устанавливается для текущего объекта; с двумя — первый аргумент строка, второй значение. Формат значений — тот же, что у `<group>.<property>.change` [контроллера формы](Form_and_navigator_controllers.md#value-formats). Свойство, не являющееся колонкой этой группы, `changeProperty` передает форме, которая разрешает его только по имени — так, как представление называет свойство везде: `<group>.<property>` — свойство этой группы, имя без группы — свойство уровня формы (пустой группы); свойство группы объектов называется с группой, передана строка или нет, а строка, переданная с именем без группы, — ошибка. `batch(fn)` делает несколько изменений вместе: каждый вызов `changeProperty` в `fn` делается сразу, а уходят они одним запросом, когда `fn` вернётся, — например, представление диаграммы Ганта при перетаскивании полосы задачи изменяет обе даты сразу:

```js
controller.batch(() => {
    controller.changeProperty('start', task, newStart);
    controller.changeProperty('end', task, newEnd);
});
```

Пакет несёт только изменения: внутри `fn` `getPropertyValues` отклоняется — вызывается его failure-callback, причина пишется в консоль, — а серверный вызов контроллера формы (`controller.form.exec`, `eval`, `evalAction`, `change`) — тоже, его Promise отвергается; делайте их до пакета или после; а изменения — только через `changeProperty` и фильтры представления (`setBooleanViewFilter`, `setDateIntervalViewFilter`), которые входят в пакет: перевод фокуса или изменение DOM внутри `fn` заставляют платформу отправлять свои запросы, а на них пакет не рассчитан. Функция, возвращающая Promise, отклоняется — но не собственный `Promise` пакета, который возвращает `changeProperty`, сделанный в `fn`, — как и в `batch` [контроллера формы](Form_and_navigator_controllers.md#batch).

`getPropertyValues` использует те же режимы `mode`, что и `<group>.<property>.getValues` контроллера формы, но свойство разрешается среди колонок этой группы, а запрос выполняется для ее текущего объекта. Результат передаётся в обработчик `ok` в виде `{ data: [ { displayString, rawString, objects }, ... ], more }`. `more` равно `true`, пока будут ещё ответы — окончательный список ответа, который сервер дал, ещё не убедившись, что несохранённые изменения формы на него не влияют, или ответ более позднего запроса. Ответ более раннего запроса, пришедший после ответа более позднего, отбрасывается:

```js
controller.getPropertyValues('name', query, result => { ... });
```

Чтобы обновлять DOM только для изменившихся значений, у _controller_ есть метод _diff_, в который передаются новый список объектов _list_ и функция-обработчик. Метод сравнивает переданный список со списком из предыдущего вызова (при первом вызове — с пустым) и выдает изменения как последовательный сценарий преобразования старого списка в новый: обработчик вызывается для каждого изменения и получает его тип (`'add'`, `'update'` или `'remove'`), позицию изменения в преобразуемом списке (для `'add'` и `'update'` она совпадает с позицией объекта в новом списке) и сам объект (для `'remove'` — удаленный, для остальных типов — новый). После этого переданный список запоминается. Два необязательных флага уточняют сравнение: при `noDiffObjects` строка одного объекта не превращается в строку другого — вместо `'update'` такая пара дает `'remove'` и `'add'`, а при `removeFirst` обработчик получает сначала все удаления — с позициями в предыдущем списке — и только затем добавления и изменения.
Пример:

```js
controller.diff(list, (type, index, object) => {
    switch (type) {
        case 'add': ...; break;
        case 'update': ...; break;
        case 'remove': ...; break;
    }
}, true, true);
```

Метод _clearDiff_ сбрасывает запомненный список — его вызывают в необязательной функции _clear_ компонента, которая вызывается при очистке представления с теми же _element_ и _controller_, чтобы следующая отрисовка началась с пустого состояния.

`setBooleanViewFilter` и `setDateIntervalViewFilter` задают серверный фильтр представления и размер страницы `pageSize`: в следующий вызов _update_ список приходит уже отфильтрованным. `setBooleanViewFilter` оставляет объекты, у которых значение свойства `property` истинно. `setDateIntervalViewFilter` оставляет объекты, у которых период от значения `startProperty` до значения `endProperty` пересекается с интервалом от `start` до `end` (значения — JS `Date`, а если `endProperty` равен `null`, оба конца периода берутся из `startProperty`). Так, встроенное представление календаря читает только события видимого диапазона дат.

Геттеры отображения позволяют компоненту использовать атрибуты дизайна, задаваемые на форме: например, представление диаграмм строит наборы данных, беря заголовок и цвета колонок из `getCaption`, `getBackground` и `getForeground`.

Правка формы — `changeObject`, `changeProperty`, `batch` и фильтры представления — идёт обычным каналом правки и не требует проверки доступа. Вызовы сервера контроллера формы, `controller.form`, её проходят ([Проверка доступа](Form_and_navigator_controllers.md#access)).

### Значение свойства {#property}

Функция отображения свойства рисует одно значение — значение своего свойства, в ячейке таблицы или на панели. Функция `update` получает его третьим аргументом, `value`:
```js
update: function (element, controller, value) {
    element.text.innerText = value || '';
}
```

Значение любого класса приходит преобразованным в значение JS так же, как в строках [React-представления](React_projection.md#values), и, кроме файлов, в том же виде передаётся в `change`.

Вместе с [`SELECT`](Properties_and_actions_block.md#options) функция отображения рисует выбор. В `value` функции `update` передаются варианты свойства, как и собственному элементу выбора платформы. Обёртка-функция вызывается с объектом `{multi, notNull, html, changeValue}`: `multi` означает выбор нескольких значений, `notNull` — обязательность выбранного значения, `html` — представления вариантов в виде HTML, а `changeValue` — передачу представления выбранного варианта явному изменению свойства.

### Контроллер свойства {#property-controller}

Методы контроллера, передаваемого в функцию _update_, не считая служебных (необязательные аргументы — в скобках):

| метод | что делает |
| --- | --- |
| `change([value])` | передает изменение значения (см. ниже); без аргумента действие изменения вызывается без значения |
| `getValues(value, ok[, fail][, count])` | список подсказок с сервера для вводимого значения `value` — тех же, что при штатном редактировании свойства |
| `isReadOnly()` | доступность свойства для правки: `null` — редактируемое, `false` — только чтение, `true` — отключено |
| `diff(list, fnc[, noDiffObjects][, removeFirst])` | вычисляет изменения массива значений — как [метод `diff` группы объектов](#diff); элементы сопоставляются по полю `objects` |
| `getColorThemeName()` | имя текущей цветовой темы: `'LIGHT'` или `'DARK'` |
| `form` | [контроллер формы](Form_and_navigator_controllers.md) |

Значение, переданное методом _change_, попадает в обработку изменения свойства так же, как значение, введенное штатным редактором, — для первичного свойства это запись значения в него. Когда переданный объект попадает в стандартное действие изменения свойства со значением пользовательского класса, указанного в блоке `CHECKED BY` [ограничения](CONSTRAINT_statement.md), он должен быть среди значений, которые оставляет фильтр: иначе изменение отклоняется. Если после свойства указано действие с ключевым словом **ON CHANGE**, вместо стандартной обработки изменения выполняется оно, а значение, переданное методом _change_, подставляется вместо ввода пользователя в его [запрос значения](../paradigm/Value_request_REQUEST.md).

Запросы метода `change` и вызовов сервера через `controller.form` выполняются на сервере в порядке вызова.

Обработчик `ok` метода `getValues` получает результат в том же формате, что и [`getPropertyValues`](#controller-methods) пользовательской группы объектов. Функция _render_ и необязательная функция _clear_, вызываемая при очистке ячейки, получают вторым аргументом сокращенный контроллер — из его методов полезен `clearDiff()`, сбрасывающий запомненный методом `diff` список.
