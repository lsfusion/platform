[Представление React](React_views.md) рисует часть формы в [интерактивном представлении](../paradigm/Interactive_view.md), и поведение формы распространяется и на эту часть: фокус, показ того, что форма ждёт сервер, клавиши и привязки мыши, событие формы `SCHEDULE` и скрытие представления вместе с контейнерами вокруг него.

### Интерактивность {#interactivity}

Чтобы читать и изменять состояние формы из компонента — выбирать строку, изменять свойство, вызывать действия — используется `props.controller`. Его методы описаны в статье [Контроллер представления React](React_view_controller.md).

Компонент, который рисует собственное поле, также сообщает форме, что пользователь в нём редактирует, чтобы во время набора `ENTER` не переводил фокус на следующий компонент, а `ESCAPE` не закрывал окно — см. [Объявление редактирования](Form_and_navigator_controllers.md#editing). Компоненту, который своих полей не рисует, объявлять нечего.

Фокусом в том, что рисует представление, распоряжается само представление: поля, в которое платформа могла бы его перевести, там нет. Поэтому `defaultComponent` у компонента, который рисует представление, ничего не делает, а [`ACTIVATE PROPERTY`](ACTIVATE_operator.md) из скрипта для свойства, которое оно рисует, — панельного или колонки строк, которые оно рисует, — приводит к ошибке. `ACTIVATE PROPERTY` для свойства, которое рисует платформа, а представление размещает через [`<Platform>`](React_platform_components.md#placing), к ошибке не приводит. Представление, которому нужно, чтобы фокус получило одно из его собственных полей, ставит его туда само — через `autoFocus` или `focus()` элемента.

<a className="lsdoc-anchor" id="form-loading"/>

Пока форма ждёт сервер, платформа показывает это на кнопке «Обновить» формы (`formRefresh`), а там, где эту кнопку рисует React, об этом говорит запись кнопки: `data.formRefresh.loading` равно `true`. Дизайн переносит кнопку в контейнер представления — `MOVE PROPERTY(formRefresh())`, — а представление рисует по записи то, что ему нужно: саму кнопку или только индикатор.

Показываются асинхронные запросы формы, какая бы её часть их ни отправила. Причины таких запросов:

- изменение свойства значением;
- смена текущего объекта, сортировок и фильтров;
- раскрытие узла дерева;
- [пакет](Form_and_navigator_controllers.md#batch);
- собственные `exec`, `eval`, `evalAction` и `change` контроллера;
- запуск [по расписанию](#live-data).

Эти запросы показываются с момента, когда первый из них прождал 20 миллисекунд, и до прихода ответа на последний из них. Запрос, ответ на который пришёл раньше, ничего не показывает, чтобы страница не мигала.

Синхронный запрос не выставляет `loading`: он блокирует ввод, и платформа вместо этого показывает свой [индикатор ожидания](../paradigm/Interactive_view.md#busy). Запуск действия через его член вне пакета — синхронный запрос, если только платформа не выполняет действие асинхронно, как выполняет выведенное с `NOWAIT`. Запись говорит `loading` и пока ждёт собственный запуск кнопки, как у любого действия.

Кнопка «Обновить», которую рисует платформа, — размещённая через [`<Platform>`](React_platform_components.md#placing) или где угодно ещё на форме, — показывает это сама, а форма без кнопки «Обновить» не показывает этого нигде. Когда это меняется, заново рисуется только представление, которое рисует кнопку:

```lsf
DESIGN orders {
    board {
        MOVE PROPERTY(formRefresh());
    }
}
```

```jsx
const { useData } = window.lsfusion;

function Busy() {
    return useData(d => d.formRefresh.loading) ? <span className="spinner"/> : null;
}
```

### Клавиши и привязки мыши {#keys}

Клавиши и привязки мыши, которые дизайн даёт тому, что рисует представление, работают так же, как в обычной форме:

- клавиша и привязка мыши свойства или действия ([`CHANGEKEY`, `CHANGEMOUSE`](Property_options.md));
- клавиши собственных кнопок формы — действий модуля `System`: `ESCAPE` закрывает форму, `ctrl ENTER` — OK;
- клавиша фильтра [группы фильтров](React_filters_and_toolbar.md#filter-groups).

Платформа привязывает их сама, и представлению для них ничего делать не нужно. Клавиша работает, пока форма показывает её компонент — его запись не `hidden` — и показано представление, которое его рисует, в каком бы элементе формы пользователь её ни нажал, и делает то же, что клавиша платформы:

- действие выполняется, как по нажатию его кнопки. Действие в строках, которые рисует представление, выполняется на текущей строке; без текущей строки клавиша достаётся другим привязкам. Действие с `CONFIRM` сначала спрашивает, окном платформы: клавиша — жест платформы, а вызов члена действия ничего не спрашивает — представление спрашивает само там, где запись говорит [`askConfirm`](React_projection.md#display-options);
- свойство, чьё изменение не просит значения — его обработчик `ON CHANGE` выполняет действие, — выполняет этот обработчик;
- клавиша фильтра выбирает фильтр, как это делает виджет платформы.

Клавиша действия или свойства, которое форма показывает только для чтения (`READONLY`, `READONLYIF`), пока это так, не берётся — она достаётся другим привязкам.

Привязка мыши берётся так же, как в обычной форме, — там, где позволяют её режимы: по умолчанию по нажатию в ячейке таблицы, которую рисует платформа, а не панели (режимы `panel` и `cell`). То, что рисует представление, — не ячейка платформы: нажатие там берёт привязку мыши, только если её режим `cell` разрешает это вне ячейки.

Режимы привязки клавиши работают как везде: с `showing=all` клавиша работает, пока форма показывает её компонент, видно представление на странице или нет, а клавише свойства группы объектов с `group=only` нужен фокус в представлении этой группы, которое рисует платформа, — то, что рисует представление, ни к какой группе не относится.

Платформа не привязывает:

- клавишу свойства или действия, которое сразу просит значение в ячейке, — изменение по умолчанию у первичного свойства, действие, которое начинается с запроса значения (`INPUT`), поле, в которое печатает сканер штрихкода: платформа открывает для него редактор в ячейке, а это поле — представления. Представление, которому такая клавиша нужна, обрабатывает её само;
- [клавиши фильтров и ввод](../paradigm/Interactive_view.md#userfilters) обычной таблицы, а также `ENTER` вниз по колонке: над строками, которые рисует представление, такой таблицы нет, и представление пользуется членами своих [управляющих элементов фильтров](React_filters_and_toolbar.md#filter-controls) и `filters.change`.

Представление платформы, которое представление размещает через [`<Platform name/>`](React_platform_components.md#placing), сохраняет свои клавиши, как и везде: они работают, пока показан его узел размещения, и перестают работать, когда представление скрывает этот узел — `<Platform>` скрывает его, пока в записи размещённого компонента установлен `hidden`.

Клавиша, нажатая в поле, которое рисует представление, доходит до формы, как любая другая. Поле, в котором пользователь набирает текст, объявляет это ([`controller.form.startEditing`](Form_and_navigator_controllers.md#editing)), чтобы привязки `ENTER`, `ESCAPE` и клавиш с режимом `editing` по умолчанию не срабатывали; клавишу, нужную самому представлению, оно останавливает в своём обработчике (`stopPropagation`).

### Обновление по расписанию {#live-data}

Изменения от [события `SCHEDULE`](../paradigm/Form_events.md#global) формы поступают через `props.data`, как любое другое изменение:

```lsf
FORM quotes 'Котировки'
    OBJECTS q = Quote
    PROPERTIES(q) READONLY symbol, price, changedAt
    EVENTS ON SCHEDULE PERIOD 2 formRefresh()
;

DESIGN quotes {
    BOX(q) {
        custom = 'QuoteBoard';
    }
}
```

[`System.formRefresh[]`](../paradigm/Form_events.md#global) возвращает всю форму на каждом запуске. Обновления одной группы объектов нет: `System.forceUpdate[STRING]` лишь применяет накопленное обновление группы в режиме ручного обновления (атрибут дизайна `enableManualUpdate`) и ничего не делает для группы, обновляемой автоматически. Поэтому табло с обновлением по расписанию держат отдельной формой только с теми свойствами, которые оно рисует, а период берут не короче, чем требуют данные.

Запуск по расписанию отличается от запроса, который компонент сделал бы сам. Собственный таймер компонента, вызывающий `controller.refresh.exec()`, опрашивает сервер так же, как нажатие на форме: синхронным запросом, блокирующим ввод до своего завершения, если действие не выведено с `NOWAIT`, — и продолжает опрос на скрытой форме.

**Скрытая форма остаётся смонтированной.** Фоновая закладка и неразмещённая форма скрыты, а не закрыты, поэтому компонент по-прежнему смонтирован, и его собственный `setInterval` продолжает срабатывать — и обращаться к серверу, — пока расписание формы приостановлено. Поэтому обновление принадлежит форме, а не компоненту.

Таймер, который компоненту всё же нужен (анимация, обратный отсчёт), как обычно снимается в очистке эффекта, но эта очистка выполняется при закрытии формы, а не при её скрытии: пока представление скрыто, его останавливает [`useVisible()`](#hidden-view).

### Скрытое представление {#hidden-view}

Платформа скрывает представление вместе с его контейнером по [правилам видимости и чтения компонентов формы](../paradigm/Form_design.md#hidden), а также в форме, которой нет на экране: в фоновой закладке, в форме, которую компонент [окна форм](React_windows.md#forms-window) никуда не поместил, или в форме другого окна, пока System.forms развёрнуто на весь экран. Компонент остаётся смонтированным и сохраняет своё состояние, а то, что он рисует, просто не видно.

То, что компонент делает сам, всё это время продолжается: таймер, запрос, анимация. `useVisible()` возвращает признак того, видно ли представление сейчас — отображается ли элемент, в котором смонтирован его корень: есть ли он на странице и нет ли над ним элемента с `display: none`, которым платформа и скрывает, — и перерисовывает компонент, когда это меняется. Поэтому собственную работу компонент делает, пока хук возвращает `true`:

```jsx
const { useVisible } = window.lsfusion;

export function Clock() {
    const visible = useVisible();
    const [now, setNow] = React.useState(() => new Date());
    React.useEffect(() => {
        if (!visible)
            return undefined;
        const timer = setInterval(() => setNow(new Date()), 1000);
        return () => clearInterval(timer);
    }, [visible]);
    return <span>{now.toLocaleTimeString()}</span>;
}
```

Прокручено ли представление в видимую область, хук не говорит. То, что компонент рисует по данным, такой проверки не требует: скрытое представление после показа рисуется заново с текущими данными, как и собственные представления платформы. А то, что он измеряет, требует: у элемента внутри скрытого контейнера нет размера, поэтому представление, которое подгоняет рисуемое под размер своего блока, — график, карта — измеряет его заново, когда станет видимым.

Вкладки и сворачиваемые контейнеры вокруг представления — часть формы, и представление читает и меняет их так же, как остальную форму, — через свойства и действия, которые ему отдаёт дизайн: [`ACTIVE TAB`](ACTIVE_operator.md) говорит, выбрана ли вкладка, [`ACTIVATE TAB`](ACTIVATE_operator.md) выбирает её, [`COLLAPSE CONTAINER`](COLLAPSE_operator.md) и [`EXPAND CONTAINER`](EXPAND_operator.md) сворачивают и разворачивают контейнер.

Действия выполняются на сервере, поэтому вкладка выбирается, когда придёт ответ сервера, а не когда представление вызывает действие. Свёрнут ли контейнер, свойством не узнать: события формы [`ON COLLAPSE` и `ON EXPAND`](Event_block.md) выполняются, когда пользователь сворачивает или разворачивает его. У контейнера, который представление рисует само, нет ни вкладки, ни сворачивания платформы — показывает его или нет само представление, — поэтому `ACTIVATE TAB`, `COLLAPSE CONTAINER` и `EXPAND CONTAINER` для него — ошибка. Для [`SHOW ... IN`](SHOW_operator.md#windowtype) также нужен контейнер, содержимое которого рисует платформа.
