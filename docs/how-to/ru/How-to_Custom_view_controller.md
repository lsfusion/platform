Пользовательское представление, написанное на JavaScript, взаимодействует с формой через объект *контроллера* — с его помощью представление задаёт текущий объект группы, изменяет значения свойств, запрашивает подсказки и вызывает действия или скрипты на сервере. Есть три вида пользовательских представлений. React-представление получает контроллер своей проекции — члены, описанные ниже, рядом с теми самыми `props.data`, которые они повторяют. Классическое представление и действие `INTERNAL CLIENT` получают контроллер формы, на котором есть только то, что есть у любого контроллера формы: форменные глаголы (`exec` / `eval` / `evalAction` / `change`) и [объявление о редактировании](#editing) (`startEditing` / `stopEditing` / `isEditing`).

Свойства и действия адресуются по их интеграционному имени — имени на форме (либо псевдониму / интеграционному имени `NEW` / `DELETE` кнопки), тому же имени, что использует [внешний JSON/REST API](How-to_Integration.md). Если `EXTID` не задал собственное имя, это имя свойства на форме, у которого отброшено всё, начиная с `(`, — поэтому `f(a)` и `f(b)`, нарисованные в одной группе, оба будут `f`: интеграционное имя само по себе не уникально.

Это имя, которым представление пользуется везде: по нему ключуется `props.data` и по нему названы все члены контроллера. Собственные операторы формы — `FILTER`, `ORDER` и `READ`, выписывающий их состояние обратно, — говорят другим именем, SID свойства на форме, причём в обе стороны. Поэтому имя, которое получило представление, не является именем, которое принимает такой оператор: перекодируйте там, где эти две стороны встречаются, — в коде `lsf`, вызывающем оператор, а не рассчитывая, что какая-то из сторон примет оба.

### Как представление получает контроллер

| представление | объявление | точка входа JavaScript | его контроллер — это |
| --- | --- | --- | --- |
| [React-представление](How-to_Custom_React_views.md) | `DESIGN c { custom = 'Name'; }` | компонент, принимающий `props` (`data`, `controller`) | `props.controller` |
| [CUSTOM группа объектов](How-to_Custom_components_objects.md) | `OBJECTS g = Cls CUSTOM 'name'` | колбэки `render` / `update` | `controller.form` |
| [CUSTOM ячейка свойства](How-to_Custom_components_properties.md) | `PROPERTIES p CUSTOM 'name'` | колбэки `render` / `update` | `controller.form` |

**React-представление** отрисовывает целый пользовательский контейнер, поэтому `controller` в его `props` — это собственный контроллер этого контейнера: методы ниже вызываются прямо на нём.

**CUSTOM группа объектов** и **CUSTOM ячейка свойства** отрисовываются классическими колбэками `render(element, controller)` / `update(element, controller, ...)` — `update` дополнительно получает `list` строк группы либо `value` ячейки. Контроллер, который они получают, — *локальный*, привязанный к этой одной группе или ячейке: он добавляет нужные этим представлениям помощники — геттеры значения, текущей строки и стилей и `diff` / `clearDiff` для группы объектов, событие правки `change` для ячейки свойства — описанные в [Пользовательские компоненты (объекты)](How-to_Custom_components_objects.md) и [Пользовательские компоненты (свойства)](How-to_Custom_components_properties.md). Локальный контроллер выставляет контроллер формы как `controller.form`, поэтому форменные методы ниже вызываются через него:

```js
const total = await controller.form.exec('recalc', orderId);
await controller.form.change('customerOrder', orderId, customerId);
```

Строки, которые получает классическое представление, несут те же `key` и `objects`, что и строки React (см. [Идентификация строки](#row-identity-contract)). Локальный `changeProperty` группы объектов также *делегирует*: для свойства, которое не является её собственной колонкой, вызов передаётся форме и разрешается в пределах всей формы, так что представление может изменить свойство, которое не отображает. Сам контроллер формы строк не принимает: его `change` называет свойство, затем значения его параметров и новое значение.

Четвёртая точка входа — действие [`INTERNAL CLIENT`](../language/INTERNAL_operator.md): привязанная к нему JavaScript-функция получает контроллер формы аргументом после параметров вызова. Контроллер [пользовательского редактора значения](How-to_Custom_components_properties.md#custom-editor) (`CHANGE`) также предоставляет контроллер формы в поле `form`.

### Контроллер формы

Контроллер — один **на проекцию**: `props.controller` React-представления принадлежит его контейнеру и называет ровно то, что показывает `props.data` этого контейнера. Объект, который классическое представление и custom-редактор ячейки получают как `controller.form`, а действие `INTERNAL CLIENT` — аргументом, — это контроллер ФОРМЫ, и на нём есть только форменные глаголы (`exec` / `eval` / `evalAction` / `change`): члены ниже говорят, что `data.<группа>.<свойство>` существует, а объекту, рядом с которым нет данных, говорить это не о чем. Он **повторяет форму `props.data`**: его члены — это записи контейнера, причём они создаются один раз, при открытии формы, и каждый лежит по тому же пути, что и его данные: то, что представление читает как `data.o.qty`, оно меняет через `controller.o.qty`, а `data.total` — через `controller.total`. Каждая группа объектов, часть которой рисует это представление, — член контроллера под своим SID, каждое свойство, ЗНАЧЕНИЕ которого это представление несёт, — член этой группы под своим интеграционным именем, а каждое свойство пустой группы (уровня формы) — член самого контроллера. Форма, в которой одно из этих имён означало бы два свойства одного контейнера, отклоняется при построении. Член *и есть* адрес: второго, строкового набора глаголов, говорящего то же самое, нет, а опечатка в имени — это несуществующий член, а не строка, которую платформе приходится проверять.

Представление читает и изменяет только части своего контейнера: его контроллер меняет то, что несут его `props.data`, и ничего больше. Общее у контейнеров — сама форма: её текущие объекты и её сессия, поэтому фильтр или текущий объект, изменённые в одном контейнере, видны в другом так же, как в стандартном клиенте.

Необязательные аргументы — в скобках.

| член | что делает | возвращает |
| --- | --- | --- |
| `<group>.change(row)` | задаёт текущий объект группы — только там, где рисуются строки группы | — |
| `<group>.<property>.change(value[, row])` | задаёт значение — на текущем объекте или на переданной строке | — |
| `<group>.<property>.exec([row])` | выполняет событие изменения свойства либо действие — на текущем объекте или на переданной строке | — |
| `<group>.<property>.getValues([object,] value[, mode], ok[, fail][, count])` | ограниченный список подсказок с сервера | — (через `ok`) |
| `<property>.change(value)` / `.exec()` / `.getValues(...)` | то же для свойства пустой группы — без строки | — |
| `<group>.expand(row)` / `.collapse(row)` / `.toggle(row)` | раскрывает или сворачивает один узел [дерева](How-to_Custom_React_views.md#trees) — узел это строка группы; только там, где рисуются строки дерева | — |
| `<group>.expandAll()` / `.collapseAll()` | раскрывает все узлы группы и групп под ней — у верхней группы всё дерево — или сворачивает узлы группы; там, где рисуются строки дерева | — |
| `properties.change([{property, object, value}])` | несколько изменений свойств ОДНИМ запросом | — |
| `exec(action, ...params)` | выполняет именованное действие | `Promise` |
| `eval(script, ...params)` | выполняет lsf-скрипт с типизированным `run` | `Promise` |
| `evalAction(script, ...params)` | выполняет тело действия (параметры `$1`, `$2`, …) | `Promise` |
| `change(property, ...keyParams, value)` | задаёт глобальное свойство | `Promise` |
| `startEditing(element)` | объявляет, что пользователь редактирует в `element` | — |
| `stopEditing(element)` | объявляет, что больше не редактирует — только если объявлен именно `element` | — |
| `isEditing(element)` | стоит ли это объявление | `boolean` |

```js
controller.o.note.change('checked');   // текущая строка группы `o`
controller.o.sum.change(100, row);     // ... переданная строка
controller.o.edit.exec(row);           // действие: выполнить на этой строке
controller.o.change(row);              // текущий объект группы
controller.o.customer.getValues(text, 'objects', ok, fail);
controller.total.change(500);          // свойство пустой группы
```

Члены — это **то, что это представление может изменить**: записи, которые оно несёт, минус то, что рисует ПЛАТФОРМА — у свойства с `LSF` есть запись (обычная запись колонки, чтобы вид нарисовал заголовок колонки) и нет члена, потому что его значение рисует и правит собственный рендерер, который это представление ставит через `<Lsf name row/>`, а у дочернего компонента с `lsf` есть только называющая его запись. Группа становится членом контроллера каждого контейнера, который рисует её часть, а свойство — членом группы там, где ИМЕННО ЭТОТ контейнер несёт его значение: списочное — там, где рисуются строки, панельное — там, где стоит само свойство. Член есть, пока есть его запись, — с самого начала, скрыта она или нет: `SHOWIF`, скрывающий свойство, оставляет член на месте, а вызов через него, пока запись `hidden`, отклоняется с ошибкой о том, что форма сейчас это свойство не показывает. Событие изменения свойства — то самое, которое пользователь запускает правкой ячейки, поэтому у свойства, которого форма не показывает, его некому вызывать. `<group>.change(row)` есть только там, где рисуются строки группы, — текущий объект выбирается среди них, — и строку принимают только там: сам `<group>.change` и член списочного свойства, который живёт там же, где строки. Член панельного свойства и член пустой группы строку не принимают: они действуют на текущих объектах. Чего представление не видит, того оно и не называет: остальная форма достигается так же, как и всё вне этой поверхности, — через `change` / `exec` / `eval` / `evalAction`, которые принимают имена и код lsf, а не имена проекции, и которые есть у любого контроллера. Вызов называет то, что меняет, членом — и в пакете тоже. У свойства, сгруппированного по колонкам, члена нет нигде — по той же причине, по которой оно не проецируется: его значения адресуются ключом «строка и колонка». (Классический `changeProperty`, который получает CUSTOM-группа объектов, — другая, более старая поверхность, и она по-прежнему называет всю форму.) Изменяющие члены ничего не возвращают: новое состояние приходит со следующим обновлением формы. Вызывающие сервер методы самого контроллера (`exec` / `eval` / `evalAction` / `change`) возвращают `Promise`.

Запуск действия через его член — `controller.o.edit.exec(row)` — тот же запрос, что и нажатие на форме: синхронный, блокирующий ввод до своего завершения и показывающий [индикатор ожидания](../paradigm/Interactive_view.md#busy) после его задержки, если действие не выведено с `NOWAIT` ([опция свойства](../language/Property_options.md) `syncType`). Собственные `exec`, `eval`, `evalAction` и `change` контроллера идут асинхронными запросами. Поэтому обновление по таймеру через контроллер не делают — см. [Живые данные](How-to_Custom_React_views.md#live-data).

`properties.change` — единственный вызов, который достаётся не через член, который он меняет: пакет охватывает несколько свойств и групп, поэтому не принадлежит ни одному члену и висит на самом контроллере. Это сокращение к тем же членам, а не второй вход: он говорит ровно то же, что и они. Свои изменения он задаёт списком `{property, object, value}` либо одним таким объектом, и `property` — это сам ЧЛЕН (`controller.o.qty`, `controller.total`), а не имя: запись, чьё `property` не является членом-свойством контроллера этого представления, отклоняется. `object` — это строка, и принимается она так же, как её принимают вызовы самого члена, — только для списочного свойства. Без неё изменение делается для текущего объекта. Отсутствующий `value` означает выполнение события изменения свойства, ровно как `exec()` члена, — и это единственная форма записи для действия. `value`, заданный как `undefined`, отклоняется, потому что очищает значение `null`. Член, чья запись `hidden`, здесь тоже отклоняется.

Имя, не являющееся идентификатором JavaScript, адресуется через скобки: свойство с `EXTID 'unit price'` — это `controller.o['unit price'].change(v)`. SID группы — всегда идентификатор: группа из нескольких объектов, чей SID был бы их именами через точку, отклоняется при построении формы, пока её не назовут (`OBJECTS pair = (d = X, t = Y)`).

Имя, которое перекрыло бы член самой поверхности, отклоняется при **построении** формы — как и [собственные зарезервированные имена проекции](How-to_Custom_React_views.md): SID группы или свойство пустой группы, совпадающее с методом контроллера (`exec`, `eval`, `evalAction`, `change`, `startEditing`, `stopEditing`, `isEditing`, `properties`) либо друг с другом (контроллер — одно пространство имён на свою проекцию, поэтому группа и свойство пустой группы, которые проецирует один и тот же контейнер, не могут оба быть `total`, — а два разных контейнера могут), а также свойство группы, названное как один из её собственных членов (`change`, а у группы дерева там, где рисуются её строки, ещё и `expand`, `collapse`, `toggle`, `expandAll`, `collapseAll`). Лечится переименованием или `EXTID`.

Те же две группы различаются ещё по двум признакам — нужна ли проверка доступа и как в них адресуется объект:

| группа | методы | проверка доступа | как передаётся объект |
| --- | --- | --- | --- |
| правка формы | `<group>.change` / `<property>.change` / `<property>.exec` / `properties.change` | нет | строка-цель — строкой данных (`row`), дескриптором (`row.objects`) или своим ключом; объект-значение (FK) — своим id |
| вызов сервера | `exec` / `eval` / `evalAction` / `change` самого контроллера | `@@api` / права администратора / `CUSTOMS` формы | объект — своим id |

Пользовательское представление обычно читает состояние из `props.data` и меняет его методами правки формы — в том числе выполняя действие, добавленное на форму, через `controller.<action>.exec()`. Методы вызова сервера (`exec` / `eval` / `evalAction` / `change`) — это запасной путь, нужный только для того, что формой не выражается: произвольного вычисления на сервере, записи в глобальное свойство, создания объекта.

Правка формы идёт обычным каналом правки и не требует проверки доступа. Вызовы сервера её проходят (см. [Вызов сервера](How-to_Custom_components_objects.md#calling-the-server)). Редактируемая строка адресуется дескриптором, а любой другой объект — значение FK или параметр действия — передаётся своим числовым id (объект lsFusion из JS передать нельзя).

#### Изменение текущего объекта и значений свойств

`controller.<group>.change(row)` задаёт текущий объект группы. Он есть только в контейнере, который рисует строки группы, а `row` — строка данных этой группы, непосредственный дескриптор `objects` либо ключ, который дала строке проекция (см. [правила идентификации](#row-identity-contract) ниже).

`controller.<group>.<property>.change(value)` изменяет свойство для текущего объекта группы, а `.change(value, row)` — для переданной строки. Аргументы идут в этом порядке, и ничего по ним не угадывается: сначала значение — оно обязательно, `null` его очищает, — затем строка, необязательная. `.exec()` выполняет событие изменения свойства — то, которое пользователь запускает правкой ячейки, — на текущем объекте, а для действия выполняет само действие, и `.exec(row)` делает это на переданной строке. Действию нечего задавать в значение, поэтому `.change` на нём отклоняется: вызывайте `exec`. Строку принимает только член списочного свойства, который живёт там, где рисуются строки группы. Член панельного свойства и член пустой группы её не принимают и действуют на текущих объектах.

```js
function orderView(props) {
    const controller = props.controller;
    return (
        <div>
            <button onClick={() => controller.o.note.change('checked')}>Отметить</button>
            {props.data.o.list.map(row =>
                <div key={row.key} onClick={() => controller.o.change(row)}>
                    {row.number.value}
                </div>)}
        </div>
    );
}
```

Значение, переданное в `change`, попадает в обработку изменения свойства, только если та запрашивает значение у пользователя — [обработка по умолчанию](../paradigm/Form_events.md#default) либо обработка с [запросом значения](../paradigm/Value_request_REQUEST.md): переданное значение подставляется вместо ввода пользователя. `null` — такое же значение, как любое другое. У действия нет значения, которое можно задать: `change` его члена отклоняется, а запускается оно через `exec`, который значения не передаёт, — `controller.o.edit.exec(row)`, — поэтому действию, запрашивающему значение у пользователя, через его член значение не передать.

`properties.change(entries)` применяет несколько изменений сразу, одним запросом. Каждая запись называет своё свойство самим членом. Запись без `object` меняет текущий объект, а запись без `value` выполняет событие изменения, как `exec`:

```js
controller.properties.change([{property: controller.o.note, value: 'checked'},
                              {property: controller.o.qty, object: row, value: 5}]);
```

Групповой объект встроенного примитивного класса — например, навигатор `DATE` — переводится к значению записью значения самого объекта (`controller.<g>.VALUE.change(d)` с настоящим JS-`Date`), вызовом `controller.<g>.change(row)` со строкой из `props.data.<g>.list` (она несёт дескриптор `objects`) либо, если группа отфильтрована по data-свойству, изменением этого свойства-фильтра. Значение-дата проходит через преобразование, ожидающее JS-`Date` (каст без проверки): аргумент не-`Date` — строка из date-инпута, timestamp — бросает `getFullYear is not a function`, поэтому передавайте настоящий `Date`, например `new Date(year, month - 1, day)`.

`.change` свойства и `properties.change` ведут себя одинаково, а формат зависит от того, что задаётся в значение:

| значение | как передаётся |
| --- | --- |
| примитив | напрямую: число — для числовых типов, строка, JS-`Date` — для `DATE` / `TIME` / `DATETIME` / `ZDATETIME`, логическое значение, `null` — для очистки |
| `JSON` | JS-объект или массив (сериализуется в JSON) |
| объект (значение FK) | id целевого объекта — `row.key` его строки (для группы с одним объектом это уже его числовой id) либо id-свойство на форме (например, `LONG(obj)`), но не дескриптор |

:::info
Передача дескриптора (`otherRow.objects`) в качестве значения FK молча выставляет `NULL`, без ошибки. Дескриптор нужен только для аргумента-строки (редактируемая строка, `object` записи пакета) и для `<group>.change`. Чтобы задать FK, передавайте id целевого объекта.
:::

В обратную сторону формат тот же: значение объектного свойства приезжает в строку данных этим же числовым id, поэтому его можно сравнить с `row.key` целевой строки (в группе с одним объектом) или передать обратно значением FK без преобразований.

Как и правка пользователя в штатной таблице, изменение выполняется в [сессии изменений](../paradigm/Change_sessions.md) формы: представление сразу видит новое значение в `props.data`, а в базу данных оно попадает при применении сессии — кнопкой «Сохранить» либо действием с оператором [`APPLY`](../language/APPLY_operator.md). Если редактируемое свойство помечено на форме [опцией `APPLY`](../language/Properties_and_actions_block.md#options), его стандартная обработка изменения применяет правку сразу (по умолчанию — фиксируя всю сессию формы), поэтому отдельное сохранение после `.change` не нужно. Подробности описаны у опции. Для простой правки из представления — перенос, изменение размера, правка значения по месту — это предпочтительнее отдельного серверного действия. Серверное действие (`controller.exec`) остаётся для того, что правкой свойства не выражается: создания объекта (`NEW`), многошаговой логики, открытия формы.

```js
// перенос объекта к другому родителю и правка примитива одним вызовом:
// значение FK — id целевого объекта (row.key целевой строки), значение-примитив — напрямую
controller.properties.change([{property: controller.i.parent, object: item, value: targetColumn.key},
                              {property: controller.i.value, object: item, value: 5}]);
```

#### Запрос значений

`getValues` запрашивает у сервера ограниченный список подсказок для свойства — список подсказок, а не полный `SELECT DISTINCT`. Результат передаётся в обработчик `ok` в виде `{ data: [ { displayString, rawString, objects }, ... ], more }`. `more` равно `true` у ответа, который сервер дал, ещё не убедившись, что несохранённые изменения формы на него не влияют: тогда `ok` вызывается ещё раз, с окончательным списком.

```js
controller.<group>.<property>.getValues([object,] value[, mode], ok, fail[, count]);
```

- `value` — вводимая строка запроса для сопоставления.
- `object` — необязательная строка, которую принимает только член списочного свойства (строка данных, непосредственный дескриптор или ключ строки — ключ только вместе с `mode`, поскольку перед одним `value` строковый аргумент читается как запрос `value`), ограничивающая запрос этой строкой. Опускается для текущего объекта.
- `mode` — одно из:

  | `mode` | результат | `item.objects` |
  | --- | --- | --- |
  | `'objects'` (по умолчанию) | подходящие `OBJECTS` свойства — выбор объекта | непосредственный дескриптор `objects` этого объекта |
  | `'values'` | различные значения свойства | `null` (используйте `displayString` / `rawString`) |
  | `'change'` | подсказки времени правки свойства | зависит от свойства |

  `'change'` отражает то, как свойство *редактируется* — пользовательский список `INPUT`, ограничение `notNull` или пользовательское действие изменения, — а не уже имеющиеся различные значения. Для свойства, которое в этом контексте изменить нельзя (например, только для чтения или вычисляемое без действия изменения), таких подсказок нет и вызывается `fail`, тогда как `'values'` всё равно вернёт его различные значения.

- `ok(result)` / `fail()` — обработчики успеха и ошибки.
- `count` — увеличивает число запрашиваемых элементов, для постраничной загрузки.

`item.objects` из результата режима `'objects'` можно передать напрямую обратно как строку, чтобы действовать с выбранным объектом: в `.change` группы, чтобы сделать его текущим, или как `row` в `.change(value, row)` или `.exec(row)` списочного свойства. Значением он не бывает никогда: дескриптор, переданный как значение FK, молча выставляет `NULL` (см. выше), а FK задаётся id объекта:

```js
controller.c.customer.getValues(text, 'objects',
    result => result.data.forEach(item => console.log(item.displayString)),
    () => console.log('failed'));

// выбор первой подсказки как покупателя группы
controller.c.customer.getValues(text, 'objects', result => {
    const item = result.data[0];
    if (item) controller.c.change(item.objects);
}, () => {});
```

#### Вызов сервера {#calling-the-server}

`exec`, `eval`, `evalAction` и `change` выполняются на сервере и возвращают `Promise`. Они проходят ту же авторизационную проверку и преобразуют результат в значение JS так же, как серверные вызовы классического представления, — описание проверки доступа, привязки параметров и таблицу преобразования результата в JS см. в разделе [Вызов сервера](How-to_Custom_components_objects.md#calling-the-server). Сквозной пример этих вызовов из представления CUSTOM — в статье [How-to: Пользовательские компоненты (вызовы сервера)](How-to_Custom_components_server_calls.md).

- `exec(action, ...params)` — выполняет именованное действие. Разрешается его значением `RETURN`. `action` — это имя действия: запись `CUSTOMS` формы — по имени, которое у неё там, или действие проекта — по его [имени](../language/IDs.md), с пространством имён и сигнатурой в квадратных скобках, когда они нужны, чтобы выбрать одно: `runReport[Order]` среди перегруженных. Но не `saveFilters()`, как написали бы в скрипте: на такое имя ответ — «Action was not found».
- `eval(script, ...params)` — выполняет lsf-скрипт, определяющий собственное действие `run` (типизированные параметры).
- `evalAction(script, ...params)` — выполняет тело действия, обёрнутое в действие `run`, с параметрами `$1`, `$2`, ….
- `change(property, ...keyParams, value)` — изменяет глобальное свойство. Последний аргумент — значение, предшествующие — ключи. Если значением свойства является объект, значением передаётся его id, и платформа присваивает объект с этим id — диалог выбора объекта открывается только при интерактивном редактировании.

Параметры передаются как обычные значения JS (число, строка, логическое значение, `Date`, объект/массив для `JSON`-параметра). Объект lsFusion передаётся своим числовым id. Если параметр действия типизирован классом, платформа сама находит объект этого класса по id — ручной поиск не нужен. Дескриптор строки в параметре объектом не является: для типизированного классом параметра вызов завершается ошибкой, поэтому передавайте id.

Этот id — `row.key` строки этого объекта (см. [Идентификация строки](#row-identity-contract)) либо свойство формы со значением-id. Передавать его нужно числом: ключ, взятый из `data.<группа>.byKey` или `data.<группа>.keys`, — *строка*, потому что ключи объекта в JS всегда строки, а строка в типизированном классом параметре отклоняется с ошибкой `Number is required`.

```js
const total = await controller.exec('recalc', orderId);
const doubled = await controller.eval('run(INTEGER a) { RETURN a * 2; }', 21); // 42
await controller.change('archived', orderId, true);
```

Вызов после закрытия формы *отклоняется* с ошибкой `Form is closed` — он никогда не зависает, — поэтому `await` на закрытой форме попадает в ветку `catch`.

#### Объявление редактирования {#editing}

Пока форма редактирует, привязка, у которой область `editing` задана по умолчанию, не срабатывает для события, пришедшего изнутри редактируемого элемента: `ENTER` не переводит фокус на следующий компонент, `ESCAPE` не закрывает модальное окно, а горячая клавиша, заданная через [`CHANGEKEY`](../language/Property_options.md), не выполняется. Привязка, объявленная с `editing=all`, срабатывает в любом случае.

Редакторы, созданные ею самой, форма знает. Поля, которое представление нарисовало себе само, она не знает, поэтому представление объявляет его:

- `startEditing(element)` — с этого момента пользователь редактирует в `element`;
- `stopEditing(element)` — пользователь больше не редактирует в `element`, причём объявление снимается, только если объявлен именно `element`;
- `isEditing(element)` — объявлен ли `element`.

Объявление на форме одно: объявление другого элемента заменяет предыдущее. Пока открыт собственный редактор формы, он имеет приоритет над объявлением, и объявление читается снова, когда это редактирование заканчивается.

Пока объявление стоит, перечисленные привязки не срабатывают для событий из `element` и из всего, что внутри него. Представление, которое ничего не объявило, сохраняет прежнее поведение: `ENTER` переводит фокус на следующий компонент, `ESCAPE` закрывает окно — из нарисованного представлением поля так же, как откуда угодно ещё.

```jsx
function Note({ controller }) {
    return <textarea onFocus={e => controller.startEditing(e.target)}
                     onBlur={e => controller.stopEditing(e.target)}/>;
}
```

В этом примере объявление делается по фокусу. Собственный редактор свойства начинает редактирование с первого набранного символа, а не по фокусу.

Объявление на обёртке покрывает все поля внутри неё — в том числе вложенный [`lsf`-компонент](How-to_Custom_React_views.md#lsf-child) и редактор, который платформа рисует в нём. Если это не нужно, объявляйте более узкий элемент.

Снимать объявление — обязанность представления, и не только по blur: снимайте его, когда элемент удаляется или представление размонтируется. Забытое объявление не даёт этим привязкам срабатывать для событий внутри этого элемента, пока форма открыта.

Объявление не начинает редактирование свойства: коммитить и отменять нечего, и `ENTER` ничего не сохраняет. Чтобы из представления редактировалось *свойство*, поставьте его через [`<Lsf name/>`](How-to_Custom_React_views.md#lsf-child) — платформа нарисует там свой редактор, и объявлять ничего не нужно.

Отдельная клавиша, нужная представлению независимо от состояния редактирования, — его собственная горячая клавиша — это другое: остановите событие в обработчике (`stopPropagation`), и форма его не получит.

### Контроллер навигатора {#navigator-controller}

Действие [`INTERNAL CLIENT`](../language/INTERNAL_operator.md), помещённое в [`NAVIGATOR`](../language/NAVIGATOR_statement.md), тоже получает контроллер, но навигаторный: формы здесь нет, поэтому нет и перечисленных выше методов формы. Есть четыре серверных вызова — `exec`, `eval`, `evalAction`, `change`, — которые выполняются в собственной сессии навигатора, новой на каждый вызов и никогда не применяемой, поэтому сделанное здесь `change` не сохраняется. И есть `activate`:

- `activate(canonicalName[, event])` — делает то же, что нажатие на этот элемент навигатора: выбирает папку либо выполняет действие, открывая его форму так же оптимистично. `canonicalName` — [каноническое имя](../language/IDs.md) элемента. `event` — событие нажатия, React-овское или браузерное, и при вызове из кода, у которого события нет, его можно не передавать.

Активация несуществующего элемента или скрытого собственным `SHOWIF` бросает исключение. О завершении выполненного действия не сообщается, как не сообщает о нём и нажатие.

```js
window.openMonthlyReport = function (controller) {
    controller.activate('Reporting.monthly');
};
```

```lsf
openMonthlyReport 'Отчёт за месяц' () { INTERNAL CLIENT 'openMonthlyReport'; }

NAVIGATOR {
    NEW openMonthlyReport WINDOW system PARENT;
}
```

### Идентификация строки {#row-identity-contract}

Метод, адресующий строку, принимает одно из:

- объект строки данных, полученный представлением (из `props` React либо из списка `update` классического представления);
- копию такой строки через spread или `Object.assign` — перечислимый дескриптор `objects` копируется вместе с ней, поэтому копия разрешается в тот же объект;
- непосредственный дескриптор `objects` — `row.objects` либо `item.objects` из результата `getValues` в режиме `'objects'`;
- **ключ**, который дала строке проекция, — `row.key` либо ключ из `data.<group>.keys` / `byKey`. Строку принимают только там, где рисуются строки её группы, поэтому у этого представления всегда есть `byKey`, в котором ищется ключ: он ищется среди строк группы самого члена, а ключ, не называющий там ни одной строки, завершается ошибкой. Именно это позволяет представлению вернуть то, что оно получило: `byKey` — JS-объект, и `Object.keys()` по нему даёт строки, так что прошедший через него ключ больше не несёт того типа, которым был записан `row.key`. У классического представления такого индекса нет, поэтому его `changeProperty` принимает строку или её дескриптор. Там, где строку и значение различают по одному аргументу, — запрос `value` у `getValues`, — голый ключ читается как значение, поэтому передавайте туда саму строку.

При этом для группы с одним объектом пользовательского класса значение `row.key` численно равно id этого объекта, поэтому его можно передать как id целевого объекта в серверный вызов или в значение FK — отдельное свойство для собственного id строки создавать не нужно.

Если явный аргумент-строка не является ни одним из них, платформа не подставляет молча текущую строку: вызов завершается ошибкой с указанием того, что ожидалось, вместо действия над другой строкой. Не принимается и строка *другой* группы: `controller.<group>.change(row)`, `change(value, row)` / `exec(row)` члена списочного свойства и запись `properties.change` — все говорят, чья строка имеется в виду, — группы члена, — а строка другой группы несёт объекты только той группы, поэтому остальные были бы взяты из текущих и вызов пришёлся бы на строку этой группы, которую никто не называл. Внутри дерева строка группы НИЖЕ в этом смысле не является строкой другой группы: её ключ — весь путь до неё, поэтому она называет ровно одну строку каждой группы выше, и там она принимается — ровно так же, как её принимает `<group>.change`.
