Пользовательское представление, написанное на JavaScript, взаимодействует с формой через объект *контроллера* — с его помощью представление задаёт текущий объект группы, изменяет значения свойств, запрашивает подсказки и вызывает действия или скрипты на сервере. Есть три вида пользовательских представлений. React-представление получает контроллер своей проекции — члены, описанные ниже, рядом с теми самыми `props.data`, которые они повторяют; классическое представление и действие `INTERNAL CLIENT` получают контроллер формы, на котором есть только форменные глаголы (`exec` / `eval` / `evalAction` / `change`).

Свойства и действия адресуются по их интеграционному имени — имени на форме (либо псевдониму / интеграционному имени `NEW` / `DELETE` кнопки), тому же имени, что использует [внешний JSON/REST API](How-to_Integration.md). Если `EXTID` не задал собственное имя, это имя свойства на форме, у которого отброшено всё, начиная с `(`, — поэтому `f(a)` и `f(b)`, нарисованные в одной группе, оба будут `f`: интеграционное имя само по себе не уникально.

Это имя, которым представление пользуется везде: по нему ключуется `props.data` и по нему названы все члены контроллера. Собственные операторы формы — `FILTER`, `ORDER` и `READ`, выписывающий их состояние обратно, — говорят другим именем, SID свойства на форме, причём в обе стороны. Поэтому имя, которое получило представление, не является именем, которое принимает такой оператор: перекодируйте там, где эти две стороны встречаются, — в коде `lsf`, вызывающем оператор, а не рассчитывая, что какая-то из сторон примет оба.

### Как представление получает контроллер

| представление | объявление | точка входа JavaScript | его контроллер — это |
| --- | --- | --- | --- |
| [React-представление](How-to_Custom_React_views.md) | `DESIGN c { custom = 'Name'; }` | компонент, принимающий `props` (`data`, `controller`) | `props.controller` |
| [CUSTOM группа объектов](How-to_Custom_components_objects.md) | `OBJECTS g = Cls CUSTOM 'name'` | колбэки `render` / `update` | `controller.form` |
| [CUSTOM ячейка свойства](How-to_Custom_components_properties.md) | `PROPERTIES p CUSTOM 'name'` | колбэки `render` / `update` | `controller.form` |

**React-представление** отрисовывает целый пользовательский контейнер, поэтому `controller` в его `props` — это собственный контроллер этого контейнера: методы ниже вызываются прямо на нём.

**CUSTOM группа объектов** и **CUSTOM ячейка свойства** отрисовываются классическими колбэками `render(element, controller)` / `update(element, controller, ...)` — `update` дополнительно получает `list` строк группы либо `value` ячейки. Контроллер, который они получают, — *локальный*, привязанный к этой одной группе или ячейке: он добавляет нужные этим представлениям помощники — геттеры значения, текущей строки и стилей и `diff` / `clearDiff` для группы объектов, событие правки `change` для ячейки свойства — описанные в [Пользовательские компоненты (объекты)](How-to_Custom_components_objects.md) и [Пользовательские компоненты (свойства)](How-to_Custom_components_properties.md). Локальный контроллер выставляет контроллер формы как `controller.form`, поэтому форменные методы ниже вызываются через него:

```js
const total = await controller.form.exec('recalc', orderId);
await controller.form.change('customerOrder', orderId, customerId);
```

Строки, которые получает классическое представление, несут те же `key` и `objects`, что и строки React (см. [Идентификация строки](#row-identity-contract)), поэтому контроллер формы принимает их без изменений. Локальный `changeProperty` группы объектов также *делегирует*: для свойства, которое не является её собственной колонкой, вызов передаётся контроллеру формы и разрешается в пределах всей формы, так что представление может изменить свойство, которое не отображает.

Четвёртая точка входа — действие [`INTERNAL CLIENT`](../language/INTERNAL_operator.md): привязанная к нему JavaScript-функция получает контроллер формы аргументом после параметров вызова. Контроллер [пользовательского редактора значения](How-to_Custom_components_properties.md#custom-editor) (`CHANGE`) также предоставляет контроллер формы в поле `form`.

### Контроллер формы

Контроллер — один **на проекцию**: `props.controller` React-представления принадлежит его контейнеру и называет ровно то, что показывает `props.data` этого контейнера. Объект, который получают классическое представление, custom-редактор ячейки или действие `INTERNAL CLIENT`, — `controller.form` — это контроллер ФОРМЫ, и на нём есть только форменные глаголы (`exec` / `eval` / `evalAction` / `change`): члены ниже говорят, что `data.<группа>.<свойство>` существует, а объекту, рядом с которым нет данных, говорить это не о чем. Он **повторяет форму `props.data`**: то, что представление читает как `data.<group>.<property>`, оно меняет как `controller.<group>.<property>.change(...)`. Каждая группа объектов — член контроллера под своим SID, каждое отрисованное в ней свойство — член группы под своим интеграционным именем, а каждое форменное (не относящееся к группе) свойство — член контроллера напрямую, — если это имя выделяет один адресуемый драв, о чём и вся остальная страница. Член *и есть* адрес: второго, строкового набора глаголов, говорящего то же самое, нет, а опечатка в имени — это несуществующий член, а не строка, которую платформе приходится проверять. Необязательные аргументы — в скобках.

| член | что делает | возвращает |
| --- | --- | --- |
| `<group>.change(object)` | задаёт текущий объект группы | — |
| `<group>.<property>.change([object,] [value])` | задаёт значение либо выполняет действие — на текущем объекте или на переданной строке | — |
| `<group>.<property>.getValues([object,] value[, mode], ok[, fail][, count])` | ограниченный список подсказок с сервера | — (через `ok`) |
| `<property>.change(...)` / `<property>.getValues(...)` | то же для форменного (не относящегося к группе) свойства | — |
| `properties.change([{property, object, value}])` | несколько изменений свойств ОДНИМ запросом | — |
| `exec(action, ...params)` | выполняет именованное действие | `Promise` |
| `eval(script, ...params)` | выполняет lsf-скрипт с типизированным `run` | `Promise` |
| `evalAction(script, ...params)` | выполняет тело действия (параметры `$1`, `$2`, …) | `Promise` |
| `change(property, ...keyParams, value)` | задаёт глобальное свойство | `Promise` |

```js
controller.o.note.change('checked');   // текущая строка группы `o`
controller.o.sum.change(row, 100);     // ... переданная строка
controller.o.edit.change(row);         // действие: выполнить на этой строке
controller.o.change(row);              // текущий объект группы
controller.o.customer.getValues(text, 'objects', ok, fail);
controller.total.change(500);          // форменное свойство
```

Члены — это **то, что проецирует собственный контейнер представления**: те же группы и свойства, что несёт `props.data`. Группа становится членом, когда её проецирует React-контейнер, а членом группы — каждое свойство, которое она рисует. Чего представление не видит, того оно и не называет: остальная форма достигается так же, как и всё вне этой поверхности, — через `change` / `exec` / `eval` / `evalAction`, которые принимают имена и код lsf, а не имена проекции, и которые есть у любого контроллера. Этими четырьмя глаголами `controller.form` классического представления и исчерпывается: члены и `properties.change` существуют только рядом с `props.data`. У свойства, сгруппированного по колонкам, члена нет нигде — по той же причине, по которой оно не проецируется: его значения адресуются ключом «строка и колонка». (Классический `changeProperty`, который получает CUSTOM-группа объектов, — другая, более старая поверхность, и она по-прежнему называет всю форму.) Изменяющие члены ничего не возвращают: новое состояние приходит со следующим обновлением формы. Вызывающие сервер методы (`exec` / `eval` / `evalAction` / `change`) возвращают `Promise`.

`properties.change` — единственный вызов, который сам называет свои свойства, а не достаётся через них: пакет охватывает несколько свойств и групп, поэтому не принадлежит ни одному члену и висит на том уровне, чьими членами эти свойства и являются. Это сокращение к тем же членам, а не второй вход: он говорит ровно то же, что и они, и свойство без члена отклоняет так же. Свои изменения он задаёт списком `{property, object, value}` либо одним таким объектом. `property` — это `'property'` либо `'groupSID.property'`. Голое имя читается так же, как `controller.<имя>`: это форменное свойство с таким именем, если форма его показывает; иначе — единственная группа объектов, в которой оно нарисовано, а имя, нарисованное в нескольких группах, завершается ошибкой, а не меняет не ту группу. Отсутствующий `object` означает текущий объект группы этого свойства, а отсутствующий `value` — выполнение свойства, ровно как `.change()` члена без аргументов.

SID группы пишется как член, поэтому SID, не являющийся идентификатором JavaScript, — группа из нескольких объектов названа всеми ими, `df.dt` — адресуется через скобки: `controller['df.dt'].name.change(v)`. То же и для свойства.

Имя, которое перекрыло бы член самой поверхности, отклоняется при **построении** формы — как и собственные зарезервированные имена проекции: SID группы или форменное свойство, совпадающее с методом контроллера (`exec`, `eval`, `evalAction`, `change`, `properties`) либо друг с другом (контроллер — одно пространство имён на свою проекцию, поэтому группа и форменное свойство, которые проецирует один и тот же контейнер, не могут оба быть `total`, — а два разных контейнера могут), а также свойство группы, названное как один из её собственных членов (`change`). Лечится переименованием или `EXTID`.

Те же две группы различаются ещё по двум признакам — нужна ли проверка доступа и как в них адресуется объект:

| группа | методы | проверка доступа | как передаётся объект |
| --- | --- | --- | --- |
| правка формы | `<group>.change` / `<property>.change` / `properties.change` | нет | строка-цель — строкой данных (`row`), дескриптором (`row.objects`) или, на форме с React-проекцией, своим ключом; объект-значение (FK) — своим id |
| вызов сервера | `exec` / `eval` / `evalAction` / `change` | `@@api` / права администратора / `CUSTOMS` формы | объект — своим id |

Пользовательское представление обычно читает состояние из `props.data` и меняет его методами правки формы — в том числе выполняя действие, добавленное на форму, через `controller.<action>.change()`. Методы вызова сервера (`exec` / `eval` / `evalAction` / `change`) — это запасной путь, нужный только для того, что формой не выражается: произвольного вычисления на сервере, записи в глобальное свойство, создания объекта.

Правка формы идёт обычным каналом правки и не требует проверки доступа; вызовы сервера её проходят (см. [Вызов сервера](How-to_Custom_components_objects.md#calling-the-server)). Редактируемая строка адресуется дескриптором; любой другой объект — значение FK или параметр действия — передаётся своим числовым id (объект lsFusion из JS передать нельзя).

#### Изменение текущего объекта и значений свойств

`controller.<group>.change(object)` задаёт текущий объект группы. Здесь `object` — строка данных этой группы, непосредственный дескриптор `objects` либо ключ, который дала строке проекция (см. [правила идентификации](#row-identity-contract) ниже).

`controller.<group>.<property>.change(value)` изменяет свойство для текущего объекта группы. Чтобы адресовать конкретную строку, она передаётся первой: `.change(object, value)`. Когда свойство — действие, значение опускается: `.change()` выполняет его на текущем объекте, `.change(object)` — на переданной строке.

```js
function orderView(props) {
    const controller = props.controller;
    return (
        <div>
            <button onClick={() => controller.o.note.change('checked')}>Отметить</button>
            {props.data.o.list.map(row =>
                <div key={row.key} onClick={() => controller.o.change(row)}>
                    {row.number}
                </div>)}
        </div>
    );
}
```

В форме `.change(X)` с одним аргументом платформа определяет, значение `X` или строка, по самому `X`: он читается как строка, если разрешается в неё (строка данных либо непосредственный дескриптор), и вызов выполняется на ней; во всех остальных случаях `X` — это значение, и изменяется текущий объект. Само свойство при этом не учитывается, поэтому один и тот же аргумент всегда означает одно и то же: id, строка, число, `Date`, `null` — это значения, независимо от типа свойства и от того, как оно редактируется. Голый ключ здесь тоже значение — от значения он неотличим; чтобы сказать, что это строка, передайте оба аргумента: `.change(key, value)`. Единственное исключение — действие, которому нечего задавать в значение: аргумент, не разрешающийся в строку, завершается ошибкой с указанием того, что ожидалось, — кроме `null`, который здесь означает текущий объект, как и везде, где передаётся строка.

`properties.change(entries)` применяет несколько изменений сразу, одним запросом; запись без `object` означает текущий объект группы этого свойства:

```js
controller.properties.change([{property: 'note', value: 'checked'},
                              {property: 'o.qty', object: row, value: 5}]);
```

Групповой объект встроенного примитивного класса — например, навигатор `DATE` — переводится к значению записью значения самого объекта (`controller.<g>.VALUE.change(d)` с настоящим JS-`Date`), вызовом `controller.<g>.change(row)` со строкой из `props.data.<g>.list` (она несёт дескриптор `objects`) либо, если группа отфильтрована по data-свойству, изменением этого свойства-фильтра. Значение-дата проходит через преобразование, ожидающее JS-`Date` (каст без проверки): аргумент не-`Date` — строка из date-инпута, timestamp — бросает `getFullYear is not a function`, поэтому передавайте настоящий `Date`, например `new Date(year, month - 1, day)`.

`.change` свойства и `properties.change` ведут себя одинаково; формат зависит от того, что задаётся в значение:

| значение | как передаётся |
| --- | --- |
| примитив | напрямую: число — для числовых типов, строка, JS-`Date` — для `DATE` / `TIME` / `DATETIME` / `ZDATETIME`, логическое значение, `null` — для очистки |
| `JSON` | JS-объект или массив (сериализуется в JSON) |
| объект (значение FK) | id целевого объекта — `row.key` его строки (для группы с одним объектом это уже его числовой id) либо id-свойство на форме (например, `LONG(obj)`), но не дескриптор |

:::info
Передача дескриптора (`otherRow.objects`) в качестве значения FK молча выставляет `NULL`, без ошибки. Дескриптор нужен только для аргумента `object` (редактируемая строка) и для `<group>.change`; чтобы задать FK, передавайте id целевого объекта.
:::

В обратную сторону формат тот же: значение объектного свойства приезжает в строку данных этим же числовым id, поэтому его можно сравнить с `row.key` целевой строки (в группе с одним объектом) или передать обратно значением FK без преобразований.

Если редактируемое свойство помечено на форме модификатором `APPLY` (правка применяется сразу), `.change` фиксирует изменение немедленно. Для простой правки из представления — перенос, изменение размера, правка значения по месту — это предпочтительнее отдельного серверного действия; серверное действие (`exec`) остаётся для того, что правкой свойства не выражается: создания объекта (`NEW`), многошаговой логики, открытия формы.

```js
// перенос объекта к другому родителю и правка примитива одним вызовом:
// значение FK — id целевого объекта (row.key целевой строки), значение-примитив — напрямую
controller.properties.change([{property: 'parent', object: item, value: targetColumn.key},
                              {property: 'value', object: item, value: 5}]);
```

#### Запрос значений

`getValues` запрашивает у сервера ограниченный список подсказок для свойства. Результат передаётся в обработчик `ok` в виде `{ data: [ { displayString, rawString, objects }, ... ], more }`; `more` равно `true`, когда список усечён, поэтому это список подсказок, а не полный `SELECT DISTINCT`.

```js
controller.<group>.<property>.getValues([object,] value[, mode], ok, fail[, count]);
```

- `value` — вводимая строка запроса для сопоставления.
- `object` — необязательная строка (строка данных либо непосредственный дескриптор), ограничивающая запрос этой строкой; опускается для текущего объекта.
- `mode` — одно из:

  | `mode` | результат | `item.objects` |
  | --- | --- | --- |
  | `'objects'` (по умолчанию) | подходящие `OBJECTS` свойства — выбор объекта | непосредственный дескриптор `objects` этого объекта |
  | `'values'` | различные значения свойства | `null` (используйте `displayString` / `rawString`) |
  | `'change'` | подсказки времени правки свойства | зависит от свойства |

  `'change'` отражает то, как свойство *редактируется* — пользовательский список `INPUT`, ограничение `notNull` или пользовательское действие изменения, — а не уже имеющиеся различные значения. Для свойства, которое в этом контексте изменить нельзя (например, только для чтения или вычисляемое без действия изменения), возвращается пустой список, тогда как `'values'` всё равно вернёт его различные значения.

- `ok(result)` / `fail()` — обработчики успеха и ошибки.
- `count` — увеличивает число запрашиваемых элементов, для постраничной загрузки.

`item.objects` из результата режима `'objects'` можно передать напрямую обратно в любой `.change`, чтобы действовать с выбранным объектом:

```js
controller.c.customer.getValues(text, 'objects',
    result => result.data.forEach(item => console.log(item.displayString)),
    () => console.log('failed'));

// выбор первой подсказки как покупателя группы
controller.c.customer.getValues(text, 'objects', result => {
    const item = result.data[0];
    if (item) controller.c.change(item.objects);
}, () => {});
```

#### Вызов сервера {#calling-the-server}

`exec`, `eval`, `evalAction` и `change` выполняются на сервере и возвращают `Promise`. Они проходят ту же авторизационную проверку и преобразуют результат в значение JS так же, как серверные вызовы классического представления, — описание проверки доступа, привязки параметров и таблицу преобразования результата в JS см. в разделе [Вызов сервера](How-to_Custom_components_objects.md#calling-the-server). Сквозной пример этих вызовов из представления CUSTOM — в статье [How-to: Пользовательские компоненты (вызовы сервера)](How-to_Custom_components_server_calls.md).

- `exec(action, ...params)` — выполняет именованное действие; разрешается его значением `RETURN`.
- `eval(script, ...params)` — выполняет lsf-скрипт, определяющий собственное действие `run` (типизированные параметры).
- `evalAction(script, ...params)` — выполняет тело действия, обёрнутое в действие `run`, с параметрами `$1`, `$2`, ….
- `change(property, ...keyParams, value)` — изменяет глобальное свойство; последний аргумент — значение, предшествующие — ключи. Если значением свойства является объект, значением передаётся его id, и платформа присваивает объект с этим id — диалог выбора объекта открывается только при интерактивном редактировании.

Параметры передаются как обычные значения JS (число, строка, логическое значение, `Date`, объект/массив для `JSON`-параметра). Объект lsFusion передаётся своим числовым id; если параметр действия типизирован классом, платформа сама находит объект этого класса по id — ручной поиск не нужен. Дескриптор строки в параметре объектом не является: для типизированного классом параметра вызов завершается ошибкой, поэтому передавайте id.

```js
const total = await controller.exec('recalc', orderId);
const doubled = await controller.eval('run(INTEGER a) { RETURN a * 2; }', 21); // 42
await controller.change('archived', orderId, true);
```

Вызов после закрытия формы *отклоняется* с ошибкой `Form is closed` — он никогда не зависает, — поэтому `await` на закрытой форме попадает в ветку `catch`.

### Контроллер навигатора {#navigator-controller}

Действие [`INTERNAL CLIENT`](../language/INTERNAL_operator.md), помещённое в [`NAVIGATOR`](../language/NAVIGATOR_statement.md), тоже получает контроллер, но навигаторный: формы здесь нет, поэтому нет и перечисленных выше методов формы. Есть четыре серверных вызова — `exec`, `eval`, `evalAction`, `change`, — которые выполняются в собственной сессии навигатора, новой на каждый вызов и никогда не применяемой, поэтому сделанное здесь `change` не сохраняется; и есть `activate`:

- `activate(canonicalName[, event])` — делает то же, что нажатие на этот элемент навигатора: выбирает папку либо выполняет действие, открывая его форму так же оптимистично. `canonicalName` — [каноническое имя](../language/IDs.md) элемента; `event` — событие нажатия, React-овское или браузерное, и при вызове из кода, у которого события нет, его можно не передавать.

Активация несуществующего элемента или скрытого через `SHOWIF` бросает исключение — активация по имени достаёт ровно то, что навигатор показывает. О завершении выполненного действия не сообщается, как не сообщает о нём и нажатие.

```js
window.openMonthlyReport = function (controller) {
    controller.activate('Reporting.monthly');
};
```

```lsf
openMonthlyReport 'Отчёт за месяц' () { INTERNAL CLIENT 'openMonthlyReport'; }

NAVIGATOR {
    NEW openMonthlyReport WINDOW system PARENT;
}
```

### Идентификация строки {#row-identity-contract}

Метод, адресующий строку, принимает одно из:

- объект строки данных, полученный представлением (из `props` React либо из списка `update` классического представления);
- копию такой строки через spread или `Object.assign` — перечислимый дескриптор `objects` копируется вместе с ней, поэтому копия разрешается в тот же объект;
- непосредственный дескриптор `objects` — `row.objects` либо `item.objects` из результата `getValues` в режиме `'objects'`;
- **ключ**, который дала строке проекция, — `row.key` либо ключ из `data.<group>.keys` / `byKey`. Ключ ищется среди строк той группы, которую задаёт ИМЯ: группы, которую называет член, группы из префикса `'<группа>.<свойство>'` либо — для свойства, названного само по себе и не показанного на уровне формы, — единственной группы, на которой оно нарисовано. Ключ, не называющий ни одной строки этой группы, завершается ошибкой, а имя, не задающее группы (свойство нарисовано на нескольких), принимает строку или её дескриптор. Ищется он в индексе самой проекции, поэтому ключ разрешается на форме, где ЕСТЬ React-контейнер; классическое представление на форме без него передаёт строку или её дескриптор. Именно это позволяет представлению вернуть то, что оно получило: `byKey` — JS-объект, и `Object.keys()` по нему даёт строки, так что прошедший через него ключ больше не несёт того типа, которым был записан `row.key`. Там, где строку и значение различают по одному аргументу — `.change(X)` с одним аргументом и запрос `value` у `getValues`, — голый ключ читается как значение, поэтому передавайте туда саму строку либо оба аргумента.

При этом для группы с одним объектом пользовательского класса значение `row.key` численно равно id этого объекта, поэтому его можно передать как id целевого объекта в серверный вызов или в значение FK — отдельное свойство для собственного id строки создавать не нужно. `key`, `isCurrent`, `objects`, `background`, `foreground` и `selected` — зарезервированные имена полей строки: свойство или колонка с таким интеграционным именем перезаписала бы поле, поэтому форма, проецирующая такое имя, отклоняется при построении. Задайте ей явный `EXTID` либо переименуйте.

Если явный аргумент-объект не является ни тем, ни другим, ни третьим, платформа не подставляет молча текущую строку: вызов завершается ошибкой с указанием того, что ожидалось, вместо действия над другой строкой.
