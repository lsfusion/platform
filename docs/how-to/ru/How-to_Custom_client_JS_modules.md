В этой статье собраны типовые задачи, решаемые клиентскими модулями JavaScript, — каждая со своим решением. Сами модули описаны в статье [Клиентские модули JavaScript](../language/Client_JavaScript_modules.md).

### Папка для файла {#file-folder}

Нужно выбрать, куда положить файл клиентского кода — в _src/main/web_ для сборки или в _src/main/resources/web_ без неё — и как он будет загружаться ([Файлы без сборки](../language/Client_JavaScript_modules.md#without-the-build)).

**Автоматически — поместите его в _resources/web/init_.** Подходит для самодостаточного компонента или таблицы стилей.

**Явно — перечислите его в _onWebClientInit_.** Используйте это, когда важен порядок загрузки — сторонняя библиотека должна загрузиться раньше использующего её компонента — или для условной загрузки файла.

Для большого файла _.jsx_ без сборки задайте `jsxTransformTimeout` больше времени его преобразования или перенесите компонент на собираемый уровень _src/main/web_, где он преобразуется при сборке ([Файлы .jsx без сборки](../language/Client_JavaScript_modules.md#lightweight-jsx)).

### Функция для клиентского действия {#example}

Нужно действие, которое форматирует сумму заказа на клиенте функцией JavaScript из проекта. Решение использует именованный экспорт модуля, который компилирует сборка ([Именованные экспорты и автоматическая регистрация](../language/Client_JavaScript_modules.md#named-exports-and-auto-registration)).

Поместим небольшой модуль в _src/main/web/orderUtil.js_, экспортирующий функцию форматирования:

```js
export function formatSum(amount, currency) {
    return new Intl.NumberFormat("en-US", { style: "currency", currency }).format(amount);
}
```

Привяжем его к клиентскому действию и вызовем:

```lsf
formatOrderSum 'Format' (Order o) {
    INTERNAL CLIENT 'formatSum' PARAMS sum(o), 'USD';
}
```

Сборка компилирует _orderUtil.js_ в _web/.compiled/orderUtil.js_ и регистрирует `formatSum`. При открытии формы действие находит имя в реестре и вызывает функцию. Запись в _onWebClientInit_ для модуля не пишется.

### Стили компонента {#component-styles}

Нужно оформить компонент модуля, который компилирует сборка ([Стили](../language/Client_JavaScript_modules.md#styles)).

Рекомендуемый способ оформления:

- **CSS-модули** (`import styles from "./Component.module.css"`, применяется как `className={styles.root}`) для собственных стилей компонента.
- **Inline-стили `style={{ ... }}`** для значений, вычисляемых из данных (цвета и размеры по строке, условное оформление).
- Обычный `import "./Component.css"` (или CSS сторонней библиотеки) для библиотечных или намеренно глобальных стилей, с префиксом в именах классов. Скомпилированный _.css_ не нужно регистрировать вручную — он уже загружается автоматически.

Для полноценной системы стилей помимо статических классов подключите библиотеку CSS-in-JS времени выполнения (например, `styled-components` или `@emotion`) зависимостью `org.mvnpm`. Используйте API `styled` или `className={css(...)}`.

Нативный CSS (вложенность, пользовательские свойства) и CSS-модули покрывают большую часть того, ради чего применялись препроцессоры. Если препроцессор CSS (Sass/SCSS, Less, Stylus) или утилитарный фреймворк (Tailwind, UnoCSS) всё же нужен, сгенерируйте CSS отдельным шагом и поставьте результат обычной таблицей стилей через `onWebClientInit`.

### Цвета для тёмной темы {#dark-theme-colors}

Нужно, чтобы цвета компонента следовали цветовой теме интерфейса. Решение использует атрибут `data-bs-theme` корневого элемента страницы ([Стили](../language/Client_JavaScript_modules.md#styles)). Основные правила задают цвета светлой темы, а правила, адресованные по атрибуту, переопределяют их в тёмной.

```css
.board { background: #ffffff; color: #212529; }
[data-bs-theme="dark"] .board { background: #212529; color: #dee2e6; }
```
