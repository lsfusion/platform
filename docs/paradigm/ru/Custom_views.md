*Пользовательское представление* — часть [интерактивного представления](Interactive_view.md) формы или [дизайна навигатора](Navigator_design.md), которую вместо платформы рисует *клиентский код*: собственный код приложения на JavaScript, выполняемый в веб-клиенте. В десктоп-клиенте на её месте используется стандартное представление платформы.

### Виды пользовательских представлений {#kinds}

Клиентский код может рисовать следующие части интерфейса:

| Часть интерфейса | Клиентский код |
| --- | --- |
| Контейнер [дизайна формы](Form_design.md) со всем, что внутри | Компонент React |
| Таблица дерева, тулбар, управляющие элементы фильтров, группа фильтров или фильтр по свойству | Компонент React |
| [Строки группы объектов](Interactive_view.md#objects) — пользовательский вид списка наряду с таблицей, сводной таблицей, картой и календарём | Компонент React или функция JavaScript |
| [Значение свойства](Interactive_view.md#property) в ячейке таблицы или на панели | Компонент React или функция JavaScript |
| Редактор значения при изменении свойства или [вводе значения](Primitive_input_INPUT.md) — дополнение стандартного поля ввода, отдельное окно или замена содержимого ячейки | Функция JavaScript |
| Окно навигатора, окно форм, окно сообщений или расположение окон на рабочем столе | Компонент React, только в настольном веб-клиенте |

Контейнер формы можно также разметить HTML-шаблоном: дочерние компоненты в отведённые им места помещает платформа. Такой шаблон может задавать и расположение элементов окна навигатора.

### Состояние формы и его изменение {#state}

Объекты формы, текущие объекты групп, фильтры, сортировки, значения свойств и [сессия изменений](Change_sessions.md) остаются у платформы. Клиентский код получает данные для той части формы, которую рисует: прочитанные наборы объектов, текущие объекты и значения свойств. Он может использовать и заданные дизайном заголовки, цвета и доступность свойств.

Клиентский код меняет состояние формы так же, как пользователь: выбирает текущий объект, меняет значение свойства, выполняет нарисованное на форме действие. Компонент React может также менять сортировки и фильтры таблицы, а для списка вне дерева — выделение строк и колонок. Изменение свойства выполняет его событие изменения, а переданное значение подставляется вместо ввода пользователя в [запрос значения](Value_request_REQUEST.md). Источник такого изменения — [пользовательский клиентский код](Form_events.md#source) (`CUSTOM`). Изменения проходят обычные проверки правки формы и не требуют доступа к внешнему API.

### Вызовы сервера {#server-calls}

Помимо правки формы, клиентский код может вызывать на сервере действия и изменять свойства по имени, а также выполнять код на языке lsFusion. На форме эти вызовы выполняются в её сессии: изменение видно следующим вызовам и сохраняется вместе с изменениями формы. В навигаторе каждый вызов выполняется в новой сессии.

По умолчанию такие вызовы проверяются как [доступ из внешней системы](Access_from_an_external_system.md): разрешены действия и свойства, открытые внешнему API, а также вызовы пользователя, который может выполнять код в [интерпретаторе](Interpreter.md). Форма может дополнительно разрешить своему клиентскому коду вызовы отдельных действий и свойств. Выполнение произвольного кода остаётся под проверкой доступа к API.

### Компоненты платформы внутри {#platform-components}

Компонент React, рисующий контейнер, может оставить часть его содержимого платформе. Тогда платформа рисует эти компоненты, а компонент React размещает их внутри своего представления. Дочерний компонент с собственным представлением — стандартным или другим пользовательским — рисуется этим представлением.

### Скрытое пользовательское представление {#hidden}

Контейнер с пользовательским представлением скрывается так же, как любой компонент дизайна: например, на невыбранной вкладке или внутри свёрнутого контейнера. Пока форма скрывает контейнер, сервер не читает то, что рисует его представление, если те же данные не нужны показанной части формы. Форма, которая целиком не видна на экране, читается как обычно.

Компоненты платформы, которые представление React не размещает, не читаются, если те же данные не нужны показанной части формы. Их заголовки, изображения и комментарии продолжают читаться, только если эти подписи отображаются вне скрытого содержимого. Подписи действия и свойства в списке следуют видимости самого действия или свойства. Контейнер, который компонент React рисует сам, сервер считает показанным, пока компонент не сообщит, что скрывает его.

### Клавиши и редактирование {#keys}

Привязки клавиш и мыши свойств, действий и групп фильтров, которые рисует компонент React, обрабатывает платформа с учётом режимов этих привязок. Исключение — привязки, которым нужна ячейка платформы для ввода значения. Клавиши стандартной таблицы над строками, которые рисует компонент, не действуют.

Когда пользователь вводит текст в поле клиентского кода, код сообщает форме о редактировании. Тогда клавиши подтверждения и отмены, а также привязки, не работающие при редактировании, не перехватывают ввод в этом поле. Это сообщение само по себе не начинает изменение свойства и не сохраняет введённое значение.

### Модули клиентского кода {#modules}

Клиентский код хранится в проекте файлами. Они могут собираться при сборке проекта или использоваться без сборки и загружаются в веб-клиент при открытии страницы.

### Язык

[Функция JavaScript](../language/Render_functions.md#render-function), указанная в `CUSTOM 'itemCards'`, рисует строки группы товаров.

### React

- [Представления React](../language/React_views.md) описывают, что получает и вызывает компонент React, рисующий пользовательское представление.
- [Контроллеры формы и навигатора](../language/Form_and_navigator_controllers.md) дают компоненту React вызовы сервера, а на форме — изменение того, что рисуется в других контейнерах, и объединение изменений в пакет.
- [Клиентские модули JavaScript](../language/Client_JavaScript_modules.md) описывают хранение, сборку, загрузку и поиск по имени компонентов React.

### Примеры

В примерах предполагается, что объявлены класс `Item` со свойством `name[Item]` и класс `Order` со свойствами `number[Order]`, `date[Order]`, `sum[Order]`. Функция JavaScript `itemCards` и компонент React `OrderBoard` загружены в веб-клиент.

Функция JavaScript рисует строки группы товаров вместо стандартной таблицы:

```lsf
FORM items
    OBJECTS i = Item CUSTOM 'itemCards'
    PROPERTIES(i) name
;
```

Компонент React рисует весь контейнер группы заказов:

```lsf
FORM orders 'Orders'
    OBJECTS o = Order
    PROPERTIES(o) READONLY number, date, sum
;

DESIGN orders {
    BOX(o) {
        custom = 'OrderBoard';
    }
}
```
