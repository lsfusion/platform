Оператор выполнения программного кода создает [действие](Actions.md), которое во время работы сервера компилирует строку с исходным кодом на языке lsFusion и выполняет её внутри сервера с полным доступом к остальному проекту.

### Исходный код

Строка трактуется как тело свежего [модуля](Modules.md), сгенерированного платформой. Заголовок модуля платформа формирует автоматически: уникальное имя модуля плюс зависимости от всех загруженных на этот момент модулей. В режиме инструкций код может задавать пространство имён модуля и приоритеты пространств имён. Поэтому код может ссылаться на любой [элемент](Element_identification.md) проекта и сам объявлять новые локальные элементы. По умолчанию пространство имён сгенерированного модуля совпадает с его уникальным именем, а пространство имён и [приоритеты поиска](Search_.md#priority) вызывающего модуля не наследуются: если код не задаёт пространство имён или приоритеты, при поиске имени без пространства имён ни одно пространство имён проекта не имеет предпочтения.

Код, который компилирует оператор выполнения программного кода, компилируется под ещё одним кодом, если он есть, и видит его элементы вместе с тем, что видит этот код. Этот код — ближайший из тех, в которых выполняется действие: выполняющийся код, скомпилированный во время работы сервера, — другим таким оператором, [контроллером формы или навигатора](../language/Form_and_navigator_controllers.md) (`eval`, `evalAction`) либо полученный через [Action API](Access_from_an_external_system.md), — или код [формы](Forms.md), действие которой выполняется, — код, настроивший форму, иначе то, что видит код, открывший её; в потоке, запущенном на сервере [новым потоком](New_threads_NEWTHREAD_NEWEXECUTOR.md), — то, что видит код, запустивший поток, а в задаче пула — то, что видит код, создавший пул; если ничего из этого нет — код настройки приложения для соединения, если он есть. Код, настраивающий форму, компилируется так же — под тем, что видит код, открывающий форму. Код, отправленный в другое соединение, выполняется там с тем, что видит это соединение. Как и у модулей проекта, у этих элементов нет приоритета: имя без пространства имён, которое объявляют и они, и проект, неоднозначно, если пространство имён или приоритеты, заданные в коде, не выбирают одно из объявлений.

Принимаются две формы исходного кода — в зависимости от режима оператора:

-   *Режим инструкций* (по умолчанию). Строка является последовательностью инструкций. Одна из них должна создавать действие с именем `run` — именно оно и будет выполнено. Как обычное скриптовое действие, `run` может объявлять интерфейсные параметры и получать через них значения.
-   *Режим действия*. Строка трактуется как тело действия — последовательность [операторов-действий](Action_operators_paradigm.md) и объявлений локальных свойств, — которое платформа автоматически оборачивает в действие `run`. Частей заголовка модуля и других инструкций уровня модуля в этой строке быть не может. Тело обращается к runtime-аргументам eval-действия позиционно.

### Параметры

Действие, выполняющее программный код, принимает исходный код как свой первый параметр. Дополнительные значения, передаваемые оператору, становятся runtime-аргументами `run` при его вызове и подчиняются обычным правилам передачи параметров.

### Область выполнения

Скомпилированное действие `run` выполняется синхронно в [сессии](Change_sessions.md) вызывающего действия, поэтому его чтения и записи разделяют сессию, apply и транзакционное состояние с вызывающим.

### Ограничения на выполняемый код

Выполняемый код предназначен для добавления новых локальных элементов и вызова существующих. Постоянную структуру проекта он менять не может. В коде eval не могут появляться:

-   объявления новых [классов](Classes.md), [таблиц](Tables.md) и [индексов](Indexes.md)
-   глобальные [события](Events.md) и [ограничения](Constraints.md), включая формы write-события и follows-ограничения, привязанные к объявлению свойства, а также ограничение, которое неявно создаёт [рекурсия](Recursion_RECURSION.md) с политикой `CYCLES NO` (действующей по умолчанию)
-   [агрегации](Aggregations.md), а также режимы агрегации и равенства у [группировки](Grouping_GROUP.md)
-   [материализация](Materializations.md), явное размещение в таблице и not-null ограничения на свойствах
-   объявление [группы](Groups_of_properties_and_actions.md) с родительской группой из другого модуля или привязка свойства или действия к группе из другого модуля
-   добавление базовых событий к существующим действиям
-   [абстрактные](Property_extension.md) свойства и действия: добавление реализации объявленному вне кода, а также объявление в коде и использование объявленного
-   настройка [навигатора](Navigator.md), в том числе планирование его действий, а также создание или скрытие его [окон](Navigator_design.md)
-   назначение [обработки события формы](Form_events.md#property) по умолчанию для свойства или действия, а также добавление аспекта, который выполняется до или после существующего действия

[Data-свойства](Data_properties_DATA.md), объявленные внутри eval-кода, приводятся к области сессии. Постоянные data-объявления не допускаются.

### Язык

Для создания действия, выполняющего программный код, используется [оператор `EVAL`](../language/EVAL_operator.md).

[Инструкция `NAVIGATOR`](../language/NAVIGATOR_statement.md) настраивает навигатор и позволяет планировать периодические действия с помощью `SCHEDULE`. [Инструкции `WINDOW` и `HIDE WINDOW`](../language/WINDOW_statement.md) создают и скрывают окна соответственно.

[Опция действия `ASON`](../language/Action_options.md) задаёт обработку события формы по умолчанию. Инструкции [`BEFORE`](../language/BEFORE_statement.md) и [`AFTER`](../language/AFTER_statement.md) добавляют действия, которые выполняются соответственно до и после существующего действия.

### Примеры

```lsf
// тело действия задано напрямую
addProperty { EVAL ACTION 'MESSAGE \'Hello World\''; }

// произвольный скрипт, введённый пользователем
code 'Исходный код' = DATA BPSTRING[2000] ();
execute 'Выполнить код' { EVAL code(); }

// передача runtime-аргумента в выполняемое тело в режиме действия
greet 'Поприветствовать пользователя' (CustomUser u) { EVAL ACTION 'MESSAGE \'Здравствуй, \' + name($1);' PARAMS u; }

// внутренний код видит свойство, объявленное внешним кодом
nested 'Вложенный код' { EVAL 'answer() = 42; run() \{ EVAL ACTION \'MESSAGE answer();\'; \}'; }
```
