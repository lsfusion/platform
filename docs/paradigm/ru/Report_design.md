*Дизайн отчетов* определяет то, каким образом располагается каждый [отчет](Print_view.md) [формы](Forms.md) при построении результирующего документа.

### Шаблоны {#template}

Для каждого из отчетов необходимо задать специальный файл (*шаблон*), который будет использоваться для построения результирующего документа. В качестве имени шаблона конкретного отчета используется `<каноническое имя формы>_<имя первой группы объектов>`, где [каноническое имя](Naming.md#canonicalname) формы включает её пространство имён, причём каждая `.` заменяется на `_`. Считается, что у [пустой](Static_view.md#empty) группы объектов нет имени, поэтому если первая группа объектов пустая, имя шаблона просто равняется каноническому имени формы (без постфикса `_`). Пустая группа объектов всегда является первой группой объектов формы, поэтому у формы всегда есть верхний отчет, называемый по одному только каноническому имени формы, без постфикса. Если подотчеты не нужны, этот шаблон — единственный. Если цепочка зависимых групп формы образует один плоский отчет по [правилам построения иерархии отчетов](Print_view.md#buildhierarchy), используется только верхний шаблон без постфикса. Для независимой ветви или группы, явно выделенной в подотчет, используется отдельный шаблон с постфиксом `_<группа>` по первой (непустой) группе объектов подотчета. Например, у формы с двумя независимыми группами объектов будет три шаблона — один для верхнего отчета без постфикса и по одному на каждый подотчет.

В шаблоне можно использовать в качестве полей свойства групп объектов, которые входят в его отчет или в любой отчет-предок. Имя поля совпадает с именем свойства на форме.

Шаблон родительского отчета включает каждый дочерний отчет как подотчет. Свойства и фильтры подотчета используют текущие значения объектов родительского отчета в качестве значений своих верхних объектов.

По умолчанию шаблон определяется по своему имени. Также разработчик может явно задать для формы в целом или для отдельного отчета свойство, значение которого задает используемый шаблон — либо имя файла, определяемое тем же образом, либо непосредственно сам файл шаблона. В качестве параметров этого свойства можно использовать объекты формы.

Шаблоны используются только полным набором. Если шаблон хотя бы одного отчета формы не найден — ни по имени, ни через такое свойство, — все найденные шаблоны игнорируются, и для всей формы используется [автоматический дизайн](#auto). Поэтому форме с подотчетами нужен верхний шаблон, даже если в нем нет ничего, кроме элементов подотчетов. Сама подмена ошибки не дает: если часть шаблонов была найдена, в лог сервера записывается предупреждение с именем ненайденного шаблона, а если не найден ни один — не сообщается ничего.

### Свойства в колонках {#columns}

При построении документа платформа создает по одной копии на каждое значение колонки для каждого текстового поля, которое расположено непосредственно в бэнде и ссылается на свойство, показанное в [колонках](Form_structure.md#groupcolumns). Платформа делит ограничивающий прямоугольник всех текстовых полей бэнда с тем же ключом, что и у исходного поля, на равные части, по одной на каждое значение колонки. Для поля без ключа платформа делит его собственный прямоугольник. Каждая копия сохраняет относительное положение по горизонтали и ширину исходного поля в своей части. Если значений колонок нет, текстовое поле удаляется.

### Видимость свойств {#showif}

Если включен [параметр работы](Working_parameters.md) `useShowIfInReports` (по умолчанию), платформа проверяет значение объявленного поля видимости свойства в первой строке отчета. Если значение равно `NULL`, платформа удаляет каждое расположенное непосредственно в бэнде текстовое поле, значение которого задано только прямой ссылкой на поле этого свойства. Она также вырезает вертикальную полосу, которую занимало текстовое поле. Платформа обрезает части расположенных непосредственно в бэндах элементов, которые попадают в полосу, и сдвигает элементы справа от нее влево на ширину полосы. Для форматов с разбиением на страницы (всех, кроме XLS, XLSX и HTML) платформа затем пропорционально растягивает оставшиеся элементы до исходной ширины.

### Автоматический дизайн {#auto}

В случае, если при формировании отчетов не удается найти хотя бы один из шаблонов, то запускается механизм автоматического формирования шаблонов на основе текущей иерархии, который для каждого отчета создает свой отдельный шаблон, в который выносятся все необходимые свойства и подотчеты. При этом, если в один отчет входит несколько групп объектов,  то самая нижняя группа в списке будет использоваться как детализация, а для каждой верхней группы в шаблоне будет создана отдельная группировка с своим блоком, в который будут вынесены все свойства из этой группы.

### Формат шаблона {#format}

В качестве конкретной реализации механизма формирования документов используется LGPL технология [JasperReports](https://community.jaspersoft.com/project/jasperreports-library). Соответственно шаблонами являются файлы формата  jrxml, которые можно редактировать при помощи приложения [JasperSoft Studio](https://community.jaspersoft.com/project/jaspersoft-studio). В момент формирования отчета выполняется поиск файлов шаблонов с именем `<имя шаблона>.jrxml` в текущем [classpath](https://docs.oracle.com/javase/8/docs/technotes/tools/windows/classpath.html)'е сервера (в том числе во всех подкаталогах). Если хоть один файл шаблона не был найден, платформа сгенерирует некоторый автоматический дизайн. Этот дизайн, при запуске сервера из IDE и формировании отчета в режиме [предпросмотра](In_a_print_view_PRINT.md#interactive), можно при помощи соответствующих кнопок сохранить в каталог запуска (и каталог исходников), после чего отредактировать в соответствии с требованиями задачи (при этом платформа будет автоматически синхронизировать файлы в каталоге запуска и каталоге исходников).

### Язык

То, какой шаблон (файл отчета) используется для формы и ее отдельных отчетов, можно явно задать через [инструкцию `FORM`](../language/FORM_statement.md).

[Опция `SUBREPORT` блока объектов](../language/Object_blocks.md#objects) выделяет указанную группу объектов в отдельный отчет.

В статье о [шаблонах отчетов JRXML](../language/JRXML_report_templates.md) описаны классы полей, параметры подотчетов, ссылки на поля и ключи для колонок, а также объявления дополнительных полей и поля для `SHOWIF`.
