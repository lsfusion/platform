## Диагностика IDE

1. Ассистент ОБЯЗАН использовать диагностику IDE или проверку ошибок, если они доступны. Он ОБЯЗАН запускать диагностику также до внесения изменений и сравнивать результаты: большой модуль может содержать проблемы, не вызванные правкой.

2. Если вызов диагностики отменён или прерван сразу после создания или изменения файла вне IDE, ассистент ОБЯЗАН сделать паузу и повторить его, прежде чем переходить к другому способу проверки: индексация может прервать вызов. Он НЕ ДОЛЖЕН считать это отменой пользователем без подтверждения.

3. Если диагностика превысила ограничение времени клиента, ассистент ОБЯЗАН повторить вызов после завершения индексации. Инспекции большого проекта могут длиться дольше этого ограничения, даже если в вызове указано большее время ожидания. Без результата диагностики он ОБЯЗАН считать файл непроверенным. Если повторный вызов снова не вернёт результат, он ОБЯЗАН проверить файл пробным запуском или запуском сервера перед выдачей результата.

4. Если диагностика файла `.lsf` вернула пустой список проблем во время индексации или сразу после создания либо изменения этого файла вне IDE, ассистент НЕ ДОЛЖЕН считать такой результат подтверждением отсутствия ошибок в файле: по нему не видно, было ли проанализировано текущее содержимое файла. Ассистент ОБЯЗАН вызвать `lsfusion_find_elements`, указав модуль файла в `modules` и `false` в `requiredModules`, а для большого модуля — ещё и изменённые объявления в `names`. Если поиск возвращает объявления файла с их текущим кодом, ассистент ОБЯЗАН повторить диагностику. Если не возвращает, ассистент ОБЯЗАН проверить файл пробным запуском или запуском сервера перед выдачей результата.

## Изменение файлов

1. Если вызов IDE, создающий, изменяющий, переносящий или удаляющий файлы, завершился по истечении времени ожидания или с ошибкой, ассистент ОБЯЗАН сравнить состояние каждого пути, которого касался вызов, с ожидаемым результатом, прежде чем повторять вызов, вносить изменение другим способом или выдавать результат. Вызов мог применить все изменения, только часть из них или ни одного, а создаваемый им файл мог остаться пустым.

## Видимость метакода

1. Если IDE не может найти элемент, объявленный использованием метакода, ассистент ОБЯЗАН развернуть использование через `lsfusion_set_meta_visibility` (`show`) и повторить диагностику. Он ОБЯЗАН разворачивать файл, в котором применяется метакод: это может быть подключаемый модуль, а не редактируемый файл.

2. После проверки ассистент ОБЯЗАН свернуть использование (`hide`) перед коммитом.

## Поиск элементов

1. Ассистенту СЛЕДУЕТ предпочитать `lsfusion_find_elements` обычному текстовому поиску. Определив нужные типы элементов, модули и классы, он ОБЯЗАН попытаться найти элементы одним вызовом структурного поиска с правильными фильтрами.

2. Если нужное не найдено, ассистент ОБЯЗАН выполнить хотя бы один дополнительный поиск: с минимальными фильтрами для обзора проекта либо по связанным элементам, начиная с уже найденных.

3. Ассистенту СЛЕДУЕТ предпочитать поиск по ключевым словам регулярным выражениям, когда это возможно.
