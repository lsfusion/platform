## Контекст сессии

1. Ассистент ОБЯЗАН осознанно выбирать контекст выполнения: без `form` вызов выполняется в новой сессии навигатора, с `form` — в собственной сессии этой формы вместе с несохранёнными правками пользователя. Перед применением в сессии формы ассистент ОБЯЗАН включить несохранённые правки пользователя в согласованный с ним объём изменений: `APPLY` сохраняет их вместе с изменениями скрипта.

2. Ассистент НЕ ДОЛЖЕН считать ожидание ответа пользователя доказательством неудачного вызова и повторять изменяющее действие: синхронный диалог держит вызов в ожидании этого ответа.

## Клиентские операции

1. Для изменения фильтров, сортировок, текущей строки или значений, которые видит пользователь, ассистент ОБЯЗАН использовать `lsfusion_client`, а не пытаться воспроизвести эти операции интерфейса скриптом eval. Для логики приложения он ОБЯЗАН использовать `lsfusion_eval` или `lsfusion_exec`.

Например, показать только непроведённые накладные — это фильтр формы, он задаётся через `lsfusion_client`; провести накладную — это действие приложения, оно выполняется через `lsfusion_exec` или скриптом через `lsfusion_eval`.

## Настройка

[Сохранённый код настройки](../brief/Brief_via_app.md) формы компилируется при создании формы, приложения — при запуске клиента.

1. Ассистент НЕ ДОЛЖЕН утверждать, что сохранение кода настройки меняет уже открытую форму или работающий клиент: изменение появится, только когда форма будет создана или клиент запущен заново.

2. Чтобы пересоздать форму, в которой он работает, ассистенту СЛЕДУЕТ вызвать `SystemEvents.formRecreate[]` через `lsfusion_exec` с `form`, указывающим на эту форму: достаточно пересоздать её одну. Ассистент НЕ ДОЛЖЕН использовать это действие для пересоздания другой формы из навигатора: оно пересоздаёт форму, в контексте которой выполняется.

3. Перед вызовом `System.reload[]` ассистент ОБЯЗАН спросить пользователя: действие перезагружает всю страницу без подтверждения ухода, и несохранённые правки теряются во всех открытых формах, включая текущую.
