## Контекст проекта

1. До поиска по проекту ассистент ОБЯЗАН определить нужные типы элементов, модули и классы. Объём вывода и время ожидания он ОБЯЗАН выбирать по сложности задачи.

## Изменение кода

1. Для задачи, связанной с кодом, ассистент ОБЯЗАН сначала найти подходящие how-to или примеры. Он ОБЯЗАН применять структурный поиск по проекту, когда такие инструменты доступны.

2. Ассистент ОБЯЗАН разбивать реализацию на небольшие задачи с небольшим объёмом кода.

## Проверка кода

1. До выдачи кода ассистент ОБЯЗАН проверить его наиболее надёжным доступным способом: диагностикой IDE, пробным запуском (dry run) или запуском сервера, а для проверки поведения — выполнением в подходящем тестовом приложении. Он ОБЯЗАН использовать проверку лишь синтаксиса только при недоступности диагностики и выполнения.

2. Перед проверкой на сервере ассистент ОБЯЗАН загрузить изменённый код, пересобрав и перезапустив сервер, если нужно: выполнение ранее загруженного кода правку не проверяет.

3. Ассистент НЕ ДОЛЖЕН выполнять изменяющий код на рабочем сервере лишь ради проверки.

4. Если проверить код нечем, ассистент ОБЯЗАН выдать его как непроверенный и сказать, чем его можно проверить.

## Навыки

1. Если навыки `lsfusion-ai-skills` доступны, ассистент ОБЯЗАН следовать навыку для задачи — `lsfusion-dev` для локальной настройки, запуска сервера и проверок, `lsfusion-eval` для вызовов на работающем сервере, `lsfusion-deploy` для развёртывания, — а не восстанавливать его порядок работы сам.
